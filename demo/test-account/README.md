# 테스트 계정 견본 — `SAMPLE(test-account-content)`

심사위원이 테스트 계정(`test`)으로 들어왔을 때 빈 화면이 아니라 **쌓인 경험 · 써 가던 지원서**에서 바로 써 볼 수 있게 채운다(ETC#313).

## 무엇이 진짜고 무엇이 견본인가

| | |
| --- | --- |
| 견본(지어낸 것) | `sources/` 의 자료 글 7개 — 컴퓨터공학 4학년 · 백엔드 지망인 **지어낸 인물**의 README · 회고 · 회의록 · 업무일지 · 메모. 실제 사람 · 학교 · 회사가 아니다(`OO`). `applications.json` 의 지원처 2곳과 지난 지원의 확정 답 하나 |
| 진짜(실제 작동) | 그 자료에서 활동 · 경험 · 근거를 뽑는 **AI 분석**, 문항 유형 · 추천 · 되묻기를 만드는 **매칭**, 첫 문항의 **초안** — 로더가 웹과 같은 API 를 불러 운영 AI 가 만든다. 결과를 손으로 고치거나 미리 적어 두지 않는다 |

- 화면에서 견본이 드러나게: 자료 이름이 `견본-…`(근거 출처 줄에 그대로 보인다), 지원처 이름 끝에 `(견본)`.
- 경험을 DB 에 직접 넣는 `SampleSeeder`(`dev-seed-activities`)와 다르다 — 그건 AI 결과처럼 보이는 손 데이터라 공개 전에 끈다.

## 넣는 것

| 자료 | 형식 | 보여 주려는 것 |
| --- | --- | --- |
| 모여봄 README + 중간 회고 | 캡스톤 README · 회고 | 문제 해결(동시 예약 · N+1) 수치 · 내 몫 / 팀 몫 · 협업 갈등 — 회고는 「자료 더하기」(S-60)로 같은 활동에 |
| 코드랩 운영진 회의록 | 노션 회의록 모음 | 기획 · 리더십 · 일정 충돌 조율 |
| 현장실습 업무일지 | 주차별 일지 | 실무 · 사수 결정과 내 몫 구분 · 테스트 · 배운 점 |
| 교내 해커톤 메모 | 짧은 메모 | 제약(API 한도) 해결 · 한계를 밝힘 · 아쉬움 |
| 알고리즘 스터디 기록 | 목록 메모 | 꾸준함 · 방식 바꾸기 · 진행 중 활동 |
| 카페 아르바이트 메모 | 생활 메모 | 직무 밖 경험에서도 책임감 · 소통이 뽑히는지(일상과 취업 사이) |

지원:

1. **OO핀테크 백엔드 신입 공채 (견본)** — 작성 중. 문항 3개(문제 해결 700자 · 협업 500자 · 직무 역량 700자). **첫 문항만 초안까지** 만들어 두고, 나머지 두 문항은 심사위원이 추천 → 되묻기 → 초안을 직접 해 본다.
2. **OO 물류 스타트업 여름 현장실습 (견본)** — 합격 · 2025-05. 확정 답 하나(지어낸 인물의 글) — 「쓰인 지원」 · 비슷한 답(S-43)이 보인다.

분석 12회(자료 7 · 문항 4 · 초안 1) — 테스트 계정 하루 한도(200) 안이다.

## 돌리는 법 — 운영 DB 를 비운 뒤(BE#21 순서)

```bash
TEST_ACCOUNT_PASSWORD=<제출 폼에 쓸 비밀번호> python demo/test-account/load.py
# 로컬: API_BASE=http://localhost:8080 TEST_ACCOUNT_PASSWORD=... python demo/test-account/load.py
```

- Cloudflare Access 를 푼 뒤에만 운영에 닿는다(풀기 전엔 「다른 곳으로 넘어갑니다」로 멈춘다).
- 활동이 이미 있는 계정이면 멈춘다 — 두 번 넣지 않는다. AI 가 실패하면 그 자리에서 멈추니, 계정을 비우고 다시 돌린다.
- 끝나면 웹에서 `test` 로 들어가 타임라인 · 지원 화면을 한 번 훑는다. 뽑힌 경험이 어색해도 **손으로 고치지 않는다**(그게 실제 결과다) — 자료 글을 고쳐 다시 넣는다.

## 심사 중에

테스트 계정 하나를 여러 심사위원이 같이 쓴다. 누가 지우거나 고치면 다음 사람에게도 그렇게 보인다. 제출 폼에 「가입해서 빈 계정으로도 써 볼 수 있다」를 같이 적는다.
