# 모여봄 중간 회고 (2025-10-24, 7주 차)

참석: 4명 전원. 진행: 나. 기록: 기획 팀원.

## 잘된 것

- 예약 중복 문제를 부하 테스트로 먼저 재현한 덕분에, 고친 뒤 "정말 고쳐졌나"를 숫자로 말할 수 있었다.
- 금요일 데모 덕분에 조교님 피드백이 일주일 안에 반영됐다.

## 안 된 것 — API 응답 모양으로 프론트와 부딪힌 일

- 3주 차까지 API 응답 모양을 백엔드가 그때그때 정했다. 에러가 어떤 API 는 `{ "message" }`, 어떤 API 는 `{ "error": { "code" } }` 였고, 날짜도 문자열 · 숫자가 섞였다.
- 프론트 팀원이 "화면 하나 붙일 때마다 응답을 확인하느라 반나절이 간다"고 했고, 나는 처음에 "백엔드가 바쁜 시기라 나중에 맞추자"고 답했다. 그 뒤 회의 분위기가 굳었다.
- 4주 차에 프론트 팀원과 둘이 따로 30분 이야기했다. 프론트가 원한 건 모양을 다 바꾸는 게 아니라 **미리 알고 싶다**는 것이었다.
- 그래서 내가 제안해 Swagger 문서를 먼저 쓰고 프론트가 확인한 뒤 구현하는 순서로 바꿨다. 에러 모양은 `{ "error": { "code", "message" } }` 하나로, 날짜는 ISO 문자열로 정했다. 이미 만든 API 14개는 내가 이틀 걸려 맞췄다.
- 그 뒤 화면 붙이는 데 걸린 시간이 API 하나에 반나절 → 1시간 정도로 줄었다(프론트 팀원 체감).
