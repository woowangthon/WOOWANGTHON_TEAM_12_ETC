# 여름 현장실습 업무일지 — OO 물류 스타트업 백엔드 (2025-07-01 ~ 2025-08-22, 8주)

사수: 백엔드 시니어 개발자 1명. 팀: 백엔드 3명 + 나(실습생).

## 1주 차
- 사내 위키 · 코드 구조 읽기. 로컬에서 서버 띄우는 데 이틀 걸림 — 환경 변수 문서가 오래돼서 빠진 항목 5개를 찾아 위키에 더함(사수 승인).

## 2~3주 차 — 관리자 페이지 「배송 내역 엑셀 내려받기」
- 요청: 운영팀이 매일 아침 배송 내역을 화면에서 복사해 엑셀에 붙여 넣고 있었다(하루 30분 이상).
- 내가 API 와 엑셀 생성(Apache POI)을 만들었다. 처음엔 한 번에 메모리에 올려 3만 건에서 서버 메모리 경고가 났다.
- 사수 리뷰: "건수가 늘 걸 생각하라." → SXSSF 스트리밍 방식으로 바꾸고 1,000건씩 끊어 읽음. 10만 건도 메모리 경고 없이 40초 안에 내려받아짐.
- 운영팀 피드백: 아침 정리가 5분으로 줄었다.

## 4~5주 차 — 정산 배치가 가끔 두 번 도는 문제
- 증상: 한 달에 한두 번 같은 날 정산이 두 번 들어감. 서버 2대에서 같은 스케줄러가 돌고 있었다.
- 나는 원인을 로그 시각으로 찾아 사수에게 보고했고, 해결 방식(ShedLock 으로 배치 하나만 돌게)은 사수가 정했다. 나는 적용과 테스트 코드를 맡았다.
- 이 일로 처음 "재현 → 원인 → 증거(로그)" 순서로 보고서를 써 봤다.

## 6~7주 차 — 테스트 코드
- 내가 만든 엑셀 API 에 테스트가 없다는 리뷰 → 서비스 계층 단위 테스트 12개 · 통합 테스트 3개 작성.
- 리뷰에서 "트랜잭션 범위가 너무 넓다"(엑셀 생성까지 트랜잭션 안) 지적 → 조회만 트랜잭션 안에 두고 파일 생성은 밖으로 뺌.

## 8주 차 — 발표
- 팀 회의에서 8주 동안 한 일과 배운 점 15분 발표.
- 사수 평가 중: "질문을 미루지 않고, 리뷰를 받으면 다음 PR 에서 같은 지적이 나오지 않았다."

## 배운 것 (마지막 날 메모)
- 기능보다 "데이터가 열 배가 되면?"을 먼저 묻는 습관.
- 내가 다 정하지 않아도 된다 — 원인과 근거를 정리해 가져가면 결정이 빨라진다.
