## 0. 개요

> 심사 「문제 정의 20 · 차별성 15」가 여기서 나온다([`hackathon.md`](hackathon.md)). 킥오프 틀: 누가 어떤 상황에서 어려운지 → AI 가 맡을 일 → 사람이 내릴 판단.

- 한 줄: 우리 팀은 활동 · 프로젝트를 여럿 해 봤지만 지원할 때마다 그 경험을 다시 찾아 정리하는 학생 · 초기 경력자의 반복 부담을 해결하려고, AI 가 흩어진 자료에서 경험을 근거와 함께 찾아 쌓아 두고 지원할 때 맞는 경험을 꺼내 부족한 사실만 묻는 서비스를 만든다
- AI 전후 한 줄: 원래 지원서 앞에서 노션 · README · 회고를 다시 뒤져 경험을 고르고 정리하던 걸, AI 가 자료를 근거 달린 경험으로 쌓아 두고 문항마다 맞는 경험을 꺼내 부족한 것만 묻는 것으로
- 대상 · 상황: 대학 시절 여러 프로젝트 · 활동을 해 본 학생과 초기 경력자. 동아리 · 부트캠프 · 대외활동 · 인턴 · 채용 지원 문항을 만났을 때
- 문제와 근거: 같은 경험을 지원할 때마다 다시 떠올리고 다시 쓴다. 학교 비교과 「경험MAP」은 학기별 경험 회상 → 직무 역량 연결 → STAR 재구성을 엑셀로 매번 손으로 채우게 한다. PM 이 옵시디언에 경험을 직접 관리하며 겪은 시행착오(팀이 한 일이 내 일로 기록됨 등). 설문 · 인터뷰는 보강 예정
- AI 가 맡는 일: 비정형 자료에서 활동과 경험을 뽑고 원문 근거를 단다 · 지원 문항의 의도를 읽고 맞는 경험을 찾는다 · 문항에 필요한데 자료에 없는 사실을 찾아 묻는다
- 사람이 판단하는 곳: 경험이 사실인지 · 내가 한 일인지 확인하고 고친다 · 어느 경험을 강조할지 고른다 · 최종 제출 문장
- 이미 있는 것과 다른 점: TIO(경험 관리 · 자소서) · refresh.cv(경력 근거 · 이력서 · MCP) 같은 서비스가 자료 업로드 · 원문 근거 · 문항 매칭 · MCP 를 이미 상당 부분 한다 — **개별 기능은 차별점이 아니다.** 우리는 흐름 전체로 다름을 보인다: 몇 달 만에 돌아와도 자료 하나로 바로 쓰이고 → 문항에서 부족한 사실만 짧게 물어 그 답이 경험에 쌓이고 → 다음 지원 · 외부 AI(MCP)에서 그 쌓인 상태가 다시 쓰인다. 경쟁 서비스 기능은 공개 화면 기준이며, 직접 확인하지 않은 것은 「미확인」이라고 말한다

### 제품 원칙 — 화면 · AI 출력을 정할 때 기준

> 기획의 목적 · 의도 · 큰 그림은 Notion 「기획-v261101」에 있다. 에이전트가 Notion 을 못 읽어도 되도록 판단에 필요한 것만 여기 옮긴다.

- **기록을 강요하지 않는다.** 매일 쓰지 않아도, 몇 달 만에 돌아와도 쓸모 있어야 한다. 스트릭 · 점수 · 빈칸 채우기 압박을 두지 않는다.
- **AI 는 과장 · 칭찬하거나 의미를 단정하지 않는다.** 원문에서 확인한 것 · 사용자가 말한 것 · AI 해석을 구분해 보여 준다. 「자료에서 확인 안 됨」은 「경험 없음」이 아니다. 초안의 사실은 근거로 받치고, 맥락을 풀어 쓴 문장 · 연결 · 직무 관련성 · 포부는 「AI 초안 · 생각」으로 구분해 사람이 판단한다(S-27 · S-78). 수치 · 성과 · 직책은 지어내지 않고 빈칸으로 둔다. AI 가 감정을 지어내거나 새 사실을 생각으로 포장하지 않는다.
- **경험이 본체다.** 채팅창이 아니라 사용자가 쌓은 활동 · 경험 위에 AI 가 끼어든다.
- **말투는 친근하게, 정보 구조는 차분하게.** 취업 SaaS 보다 산뜻하되 유아적이지 않게. 대학생만이 아니라 직장인 · 프리랜서도 쓸 수 있는 말로.
- **경험과 자료는 사용자 것이다.** 나중에 외부 AI(MCP) · 내보내기로 꺼내 쓸 수 있게 둔다.

## 1. 요구사항

### R-01 경험 관리 — 스프린트 1

> 목표 흐름: 자료 하나를 넣으면 → 연도별 타임라인에 활동이 나타나고 → 활동을 누르면 근거 달린 경험이 보이고 → 고쳐서 저장하면 남는다.

용어 — 계약 · 코드에서 같은 뜻으로 쓴다. 화면 문구는 따로 정해도 된다.

| 용어 | 뜻 |
| --- | --- |
| 원본(Source) | 사용자가 넣은 자료 하나 — 붙여넣은 텍스트 또는 파일 |
| 활동(Activity) | 프로젝트 · 동아리 · 수업 · 대회 같은 한 덩어리. 이름 · 기간 |
| 경험(Experience) | 활동 안에서 실제로 한 일 하나 — 행동 · 결정 · 결과 · 배운 점. 활동 하나에 여럿 |
| 역량(예전 이름 「관점」) | 그 경험을 어떤 쪽으로 쓸 수 있나(기술 구현 · 문제 해결 · 협업 …). 정해진 목록에서 경험 하나에 0 ~ 3개(미결정 2). **AI 가 붙인 해석**이다 — 원문에서 확인한 사실처럼 보이지 않게 하고, 사용자가 고친다 |
| 근거(Citation) | 경험을 뒷받침하는 원본의 발췌문 |
| 출처 상태 | 원문에서 확인 / 내가 입력 / 확인 필요. 「확인 필요」는 근거가 없거나 원본에서 못 찾았거나, 외부 AI 가 고쳐 사용자가 아직 확인하지 않았다는 뜻이지(S-53) 「경험이 없다」가 아니다 |
| 수행 주체 | 나 / 팀 / 알 수 없음 |

#### F-01 자료 넣기

- 우선순위: `P0`
- 레포: FE · BE
- `S-01` 텍스트를 붙여넣거나 `.md` · `.txt` 파일 하나를 올리면 분석이 시작된다 — 완료 조건: 원본 텍스트가 저장되고, 분석 작업의 상태를 조회할 수 있다
  - 「직접 기록하기」(추가 메뉴 · 빠른 찾기 바로가기)는 새 기능이 아니라 같은 자료 넣기의 한 줄 입구다(FE#179 · 2026-11-07 PM) — 창 제목 · 안내 · 빈칸 안내만 한 줄 기록용이고 파일 올리기는 숨긴다. 분석 1회 · 외부 AI 전송 안내(S-16) · 결과(새 활동 + 같은 활동 제안 S-44)는 그대로다. 범위 제외: 기존 활동에 바로 붙이기(시안 문구 「맞는 활동에 붙여 둘게요」 — S-60 은 사용자가 활동을 고른 뒤의 일이다)
- `S-16` 자료를 넣는 곳에서, 넣은 자료가 외부 AI(LLM 제공사)로 보내져 분석된다는 것이 보인다 — 우선순위 `P0`(2026-11-02 추가: Notion 기획 6.4 「서드파티 AI 전송 전 설명」) — 완료 조건: 분석을 시작하기 전에 보인다. 제공사 이름 · 입력이 학습에 쓰이는지는 ETC `ai-scope.md` §2 의 지금 모델 기준(기본 OpenAI 유료 API — 학습에 쓰지 않음)
- `S-02` 분석 상태가 보인다: 분석 중 → 완료 / 실패 — 완료 조건: 실패하면 실패했다는 것과 「다시 시도」가 보인다(정해진 결과로 대신 채우지 않는다). 분석 중에 새로고침해도 상태가 이어진다
- `S-39` 텍스트 PDF · PPTX 파일 하나를 올려도 분석이 시작되고, 근거를 열면 **몇 쪽 · 몇 번째 슬라이드**에서 나왔는지 보인다 — 우선순위 `P1`(ETC#25 · 2026-11-05: 이력서 · 발표 자료는 PDF · PPTX 가 많다 — Notion 기획 5.A · 9.2) — 완료 조건: 글자는 **브라우저에서** 뽑아 `.md` · `.txt` 와 같은 길로 보내고, 쪽 · 슬라이드 위치는 따로 실어 BE 가 남긴다(ETC#25 결정 — 계약 `experience-api.md` 「자료 넣기」). 슬라이드는 PowerPoint 에 보이는 순서대로 센다. 글자를 하나도 못 읽는 파일(스캔 PDF · 그림뿐인 슬라이드)은 넣지 않고 「글자를 읽을 수 없어요 — 텍스트로 붙여 넣어 주세요」로 돌아간다(글자를 지어내지 않는다 · OCR 하지 않는다). 일부 쪽 · 슬라이드만 못 읽었으면 넣기 전에 몇 쪽을 못 읽었는지 보인다. 그림 속 글자 · 발표자 노트는 읽지 않고, 표는 칸의 글자만 읽는다(표 모양은 살리지 않는다). 홈 입력(S-28)에 파일을 올릴 때도 같다
- `S-59` 파일 **여러 개를 한 번에** 올리면 파일마다 원본 하나 · 분석 하나로 **차례로** 분석된다 — 우선순위 `P2`(ETC#76 · 2026-11-05 PM: 회고 · README · 이력서를 한꺼번에 넣고 싶다) · 레포 FE · BE — 완료 조건: 한 번에 최대 10개. 파일마다 분석 1회로 센다(S-15) — 남은 횟수가 파일 수보다 적으면 **하나도 넣지 않고** 이유가 보인다. 못 넣는 파일(지원하지 않는 형식 · 글자를 못 읽음 · 너무 김 — S-39)은 넣기 전에 어느 파일인지와 이유가 보이고 나머지만 넣는다. 앞 파일 분석이 끝난 뒤 다음 파일을 분석해서, 같이 넣은 앞 파일에서 생긴 활동도 같은 활동 제안(S-44)의 대상이 된다(회고와 README 를 같이 넣으면 README 쪽 활동에 「같아 보여요」). 파일마다 기다림 · 분석 중 · 완료 · 실패가 보인다. 하나가 실패해도 다음 파일은 이어 분석되고, 실패한 파일만 다시 시도한다. 창을 닫거나 새로고침해도 남은 파일 분석은 이어진다. 붙여넣기는 지금처럼 하나씩. 버린 안: FE 가 파일마다 지금 API 를 동시에 부르기(같이 넣은 파일끼리 제안이 안 붙는다) · 여러 파일을 분석 1회로 합치기(글자 한도를 나눠 쓰고 근거 위치가 섞인다)
- `S-60` 활동 세부에서 **그 활동의 자료를 더 넣는다**(「자료 더하기」 — 붙여넣기 또는 파일 하나) — 우선순위 `P2`(ETC#76 · 2026-11-05 PM) · 레포 FE · BE · AI — 완료 조건: 분석은 보통 자료 넣기와 같다(분석 1회 · S-02 상태 · 실패하면 다시 시도). AI 가 자료 속 활동 중 **이 활동과 같은 것**을 고르면, 그 경험 · 근거는 제안 없이 **바로 이 활동에 붙는다** — 사용자가 이미 활동을 골랐으므로(자동 합치기가 아니다). 결과는 S-13 합치기와 같다 — 이 활동의 이름 · 기간 · 분류가 그대로 남고 경험 · 근거가 하나도 빠지지 않는다. 자료 속 다른 활동은 보통처럼 새 활동이 되고 같은 활동 제안(S-44)을 받는다. 이 활동과 같은 것을 못 찾으면 「이 자료에서 이 활동 내용을 찾지 못했어요」가 보이고, 뽑은 활동은 새 활동으로 남는다(지우거나 합치는 건 사용자 — S-11 · S-13). 근거를 열면 새 자료 이름이 보인다(S-09). 버린 안: 자료 전체를 이 활동으로(이력서처럼 활동이 여럿 든 자료면 다른 활동 경험이 섞인다) · 보통 자료 넣기 + 제안만(이미 고른 활동을 한 번 더 누른다)
- `S-69` 같은 자료를 다시 넣으면 분석 **전에** 「이미 넣은 자료예요」와 그 자료의 이름 · 넣은 날이 보이고, 사용자가 **「그래도 넣기 / 그만」** 을 고른다 — 우선순위 `P2`(ETC#114 · ETC#186 · 2026-11-06) · 레포 FE · BE — 완료 조건: 파일 · 붙여넣기 모두 **뽑은 글자**로 비교한다(SHA-256 — 줄바꿈 종류 · 앞뒤 공백만 무시하고 그 밖의 차이는 다른 자료다). AI 를 부르지 않고, 원본을 저장하지 않으며, 분석 횟수(S-15)를 쓰지 않는다. 「그만」이면 입력이 그대로 남는다. 「그래도 넣기」는 보통 자료 넣기와 같다(분석 1회 · 새 원본 · 새 활동). 같은 사용자의 **남아 있는** 원본만 비교한다 — 분석이 실패했거나 경험을 다 지운 원본도 남아 있으면 알아본다. 비교는 자료 넣기 · 홈 입력의 하나씩 넣기에서만 한다 — 여러 파일 넣기(S-59) · 자료 더하기(S-60) · 차곡이 · 외부 AI 의 자료 넣기(S-31 · S-52)는 지금처럼 바로 넣는다. 범위 제외: 다른 사용자의 같은 자료 · 바뀐 부분만 다시 분석(ETC#114 큰 판)
- **가져오기**(S-62 ~ S-64, ETC#29 · 2026-11-06 PM) — 이미 노트 · Notion · GitHub 에 기록하는 사람이 다시 옮겨 적지 않게 한다. 셋 다 **한 번 가져오기**이고 **브라우저에서** 글자를 뽑아 지금 계약(`POST /api/sources` · `/batch`)으로 보낸다(S-39 와 같은 길 — BE · AI 는 그대로). 분석 1회 · 한도 · 상태 · 다시 시도 · 외부 AI 전송 안내는 보통 자료 넣기와 같다(S-15 · S-02 · S-16). 계정 연결(OAuth) · 동기화는 ETC#184 백로그
- `S-62` 자료 넣기에서 **폴더 하나**(옵시디언 볼트 · 노트 폴더)를 고르면 안의 노트 목록이 보이고 **10개까지 골라** 한 번에 넣는다 — 우선순위 `P2` · 레포 FE — 완료 조건: 하위 폴더까지 `.md` · `.txt` · `.pdf` · `.pptx` 를 폴더 안 경로와 함께 보인다. 점(`.`)으로 시작하는 폴더(`.obsidian` · `.trash` · `.git` …)는 읽지 않는다. 노트 하나를 체크하면 그 노트가 링크한(`[[노트]]` · `[[노트|별칭]]` · `[글](경로.md)`) 같은 폴더 안 노트도 **함께 체크**된다 — 한 단계만, 10개를 넘기지 않고, 넘어서 못 고른 수가 보인다. 함께 체크된 것은 사용자가 풀 수 있다(MOC 처럼 링크만 있는 노트를 고르면 내용이 든 노트가 따라온다 — ETC#29 메모 2026-11-03). 고른 노트는 **S-59 그대로** 노트마다 원본 하나 · 분석 1회로 차례로 분석된다(남은 횟수 · 못 넣는 파일 · 파일별 상태 · 다시 시도 모두 S-59). 원본 이름은 폴더 안 경로(`볼트/활동/바꿔요-회고.md`)라 근거에서 어느 노트인지 보인다. 링크만 있는 노트에서 나온 활동은 경험 없이 활동만 남는다(S-03). 범위 제외: 폴더 전체를 분석 1회로 합치기(S-59 버린 안) · 링크를 두 단계 넘게 따라가기 · 이미지 · 첨부 · 속성(YAML) 해석. 버린 안: 옵시디언 전용 화면(볼트도 마크다운 폴더일 뿐이다) · 링크 따라가기 없이 고르기만(MOC 를 고르면 내용 없는 활동만 남는다)
- `S-63` Notion 에서 **「Markdown & CSV」로 내보낸 ZIP** 을 올리면 안의 페이지 목록이 보이고 S-62 와 같이 10개까지 골라 넣는다 — 우선순위 `P2` · 레포 FE — 완료 조건: ZIP 은 브라우저에서 푼다. 안에 ZIP 이 또 있으면(큰 내보내기는 나눠 담긴다) 한 단계까지 푼다. `.md` 만 목록에 올리고 CSV(데이터베이스 행) · 이미지 · 첨부는 읽지 않는다. 페이지 이름 끝의 Notion 식별자(공백 뒤 32자리 16진수)는 떼고 보이며 원본 이름도 뗀 경로다. 페이지 사이 링크는 S-62 와 같이 한 단계 함께 체크된다. `.md` 가 하나도 없으면 「이 ZIP 에서 페이지를 찾지 못했어요 — Notion 에서 Markdown & CSV 로 내보냈는지 확인해 주세요」. 풀었을 때 파일 수 · 크기가 한도를 넘으면 풀지 않고 이유가 보인다(숫자는 FE 이슈에서 정한다). 올리는 자리에 Notion 에서 내보내는 길이 한 줄로 보인다. 범위 제외: Notion 계정 연결(OAuth — 페이지를 골라 바로 가져오는 TIO 방식, ETC#184) · CSV 행 분석. 버린 안: 내보내기 안내만 하고 사용자가 ZIP 을 풀어 `.md` 를 올리기(하위 페이지가 폴더마다 흩어져 있어 없으니만 못하다 — PM)
- `S-64` 자료 넣기에 **공개 GitHub 레포 링크**와 (넣으면) **내 GitHub 아이디**를 넣으면 README 와 그 레포에서 **내가 쓴 커밋 · 연 PR 의 제목**을 읽어 자료 하나로 넣는다 — 우선순위 `P2`(README 엔 누가 무엇을 했는지 없을 때가 많다 — 커밋 · PR 제목이 「내가 한 일」의 근거가 된다) · 레포 FE — 완료 조건: 로그인 없이 GitHub 공개 REST API 를 **브라우저에서** 부른다(서버 IP 하나에 요청이 몰리지 않게 — 비인증 한도가 IP 당 시간당 60회). 자료 글은 레포 이름 · 링크 · 설명 → README → 「내가 쓴 커밋 제목」(날짜와 함께 최근 100개) → 「내가 연 PR 제목」(날짜 · 상태와 함께 최근 100개) 순서이고, 넣기 전에 그 글과 커밋 · PR 수가 보인다. 커밋 · PR 절 제목은 「내가 …」로 써서 AI 가 그 줄을 수행 주체 「나」로 읽게 하고, README 의 일은 글에 「내가」가 없으면 팀 · 알 수 없음으로 남는다. 아이디를 비우면 README 만 넣는다. 아이디로 찾은 커밋 · PR 이 0개면 「이 아이디로 찾은 커밋이 없어요 — 커밋 이메일이 GitHub 계정에 연결되지 않았을 수 있어요」를 보이고 그대로 넣을지 사용자가 정한다. 커밋 본문 · 코드 · 이슈 · 리뷰는 읽지 않는다. 원본 이름은 `owner/repo (GitHub).md`. 50000자를 넘으면 README 뒤를 잘라 맞추고 잘랐다는 줄을 글에 남기며 넣기 전에 보인다. 비공개 · 없는 레포 · 읽을 것이 없음(README 도 커밋 · PR 도 없음) · 한도 걸림(403 · 429) · 연결 실패는 이유와 다시 시도 · 「본문을 붙여 넣어 주세요」로 돌아간다(정해진 글로 채우지 않는다). 범위 제외: GitHub 로그인(OAuth) · 비공개 레포 · 레포 여러 개 한 번에(ETC#184). 버린 안: README 만(내가 한 일이 빠진다) · 서버(BE · AI)에서 받기(사용자 요청이 서버 IP 하나의 비인증 한도를 같이 쓴다)

#### F-02 AI 경험 추출

- 우선순위: `P0`
- 레포: AI · BE
- `S-03` 원본 하나에서 활동 1개 이상과, 활동마다 경험 여러 개를 뽑는다. 경험마다 역량(예: 기술 구현 · 문제 해결 · 협업)이 1 ~ 3개 붙는다. 원본에 활동 이름 · 기간만 있고 한 일이 없으면(이력서 항목 · 옵시디언 MOC 의 링크 목록 등) **경험 없이 활동만** 만든다 — 경험을 지어내 채우지 않는다(2026-11-03 PM: 빠뜨리면 사용자는 빠진 줄 모른다 · 「자료에서 확인 안 됨」은 「경험 없음」이 아니다) — 완료 조건: 활동이 여럿 섞인 자료(목록형 노트 등)에서도 활동별로 나뉜다. 이름만 있는 활동도 타임라인에서 빠지지 않는다
- `S-04` 경험마다 근거가 1개 이상 붙는다. 근거가 원본에 실제로 있는지 **코드로** 확인한다 — 완료 조건: 원본에 없는 근거를 단 경험은 「확인 필요」가 된다
- `S-05` 자료에 없는 수치 · 역할 · 결과를 만들지 않는다 — 완료 조건: 원본에 수치가 없으면 경험에도 수치가 없다
- `S-06` 수행 주체를 구분한다 — 완료 조건: 원본이 「팀이 했다」면 「나」로 바꾸지 않는다. 판단할 수 없으면 「알 수 없음」

#### F-03 경험 보기

- 우선순위: `P0`
- 레포: FE · BE
- 참고(정한 것 아님): TIO 마인드맵처럼 연도 → 활동이 보이고 활동을 누르면 옆에 세부가 뜨는 흐름. 마인드맵 모양은 쓰지 않고 읽기 좋은 타임라인으로. 세부를 여는 방식(옆 패널 · 하단 시트 · 펼침)과 모양은 담당이 만들어 보고 PM 이 화면을 보며 고친다
- `S-07` 기본 화면은 **연도별 타임라인**이다. 활동이 연도 아래 시간 순으로 놓인다 — 완료 조건: 분석으로 생긴 활동이 바로 나타난다. 기간이 겹치거나 진행 중인 활동도 보인다. PC 와 모바일 폭 둘 다에서 읽힌다
- `S-08` 타임라인에서 활동을 누르면 타임라인을 떠나지 않고 그 활동의 세부(이름 · 기간 · 경험들)가 열린다. 경험은 처음엔 몇 개만 보이고 나머지는 펼쳐 본다 — 완료 조건: 경험마다 역량 · 수행 주체 · 출처 상태가 보이고, 출처 상태는 색만이 아니라 글자로도 구분된다
- `S-09` 경험에서 근거를 열면 원본 이름과 발췌문이 보인다
- `S-57` 활동마다 **분류**가 하나 붙어, 타임라인에서 분류별로 나눠 보고 거른다 — 우선순위 `P1`(ETC#173 · 미결정 5 · 2026-11-05) · 레포 FE · BE · AI — 완료 조건: 분류는 닫힌 목록 셋이다 — 프로젝트 · 일 / 공부 · 성장 / 동아리 · 대외활동(contracts README 「값 목록」 `activityCategory`). 분석이 활동을 만들 때 AI 가 하나 붙이고, 가늠이 안 되면 비워 둔다(미분류) — 억지로 고르지 않는다. AI 가 붙인 분류는 「AI 해석」으로 구분해 보인다. 사용자가 세부에서 분류를 고르거나 비울 수 있다 — 새로고침해도 남고, 고르면 「AI 해석」 표시가 사라진다. 타임라인에서 활동의 분류가 보이고 — 색만으로 구분하지 않는다 — 전체 · 분류 셋으로 거른다. 미분류 활동은 「전체」에만 보인다. 기존 활동은 다시 분석하지 않는다 — 미분류로 남는다. 활동을 합치면 남길 활동의 분류가 남고, 그 활동이 미분류면 합쳐 온 활동의 분류를 받는다. **분류는 정리용이다** — 매칭 · 초안 · 근거 점검의 판정에 쓰지 않는다(태그가 빠져도 매칭이 무너지지 않게 — 미결정 8). 범위 제외: 사용자가 분류를 더하기 · 이름 바꾸기, 역량 · 기간 · 확인 필요로 거르기(ETC#32 → S-58), MCP · 내보내기에 싣기
- `S-58` 쌓인 **경험**을 낱말로 찾고 역량 · 연도 · 출처 상태 · 활동 분류로 거른다 — 타임라인(활동 단위)을 거치지 않고 경험을 한 줄씩 훑는다 — 우선순위 `P1`(ETC#32 · 2026-11-05 PM: Notion 같은 도구에서 검색 · 거르기를 많이 쓴다) · 레포 FE · BE — 완료 조건: 결과 한 줄은 **경험** 하나다 — 본문 · 활동 이름 · 기간 · 역량(AI 가 붙인 것은 「AI 해석」) · 수행 주체 · 출처 상태(글자로도)가 보이고, 근거 발췌문 · 원본 이름을 열어 볼 수 있다. 누르면 그 활동의 세부(S-08)가 열린다. 낱말은 경험 본문 · 근거 발췌문 · 보완 문답 · 활동 이름에서 찾는다 — 공백으로 나눈 낱말 중 하나라도 들면 걸리고, 많이 맞은 것이 위다(MCP `search_experiences` 와 **같은 검색** — 같은 입력이면 같은 결과). 거르기는 역량(여러 개 고르면 하나라도 붙은 것) · 연도(활동 기간이 그해와 겹치는 것) · 출처 상태(「확인 필요」만 보기 등) · 활동 분류(S-57)이고, 낱말과 함께 모두 그리고로 묶는다. 아무것도 넣지 않으면 경험 전부가 보인다. 찾은 게 없으면 「쌓인 자료에서 찾지 못했어요」 — 「그런 경험이 없다」로 말하지 않는다. 결과가 많아 다 못 보여 주면 몇 개 중 몇 개인지 보이고 더 좁히라고 알린다. **AI 를 부르지 않는다** — 낱말 맞추기라 「동아리에서 의견 모은 적」처럼 뜻으로 묻는 건 꺼내기(S-29)의 몫이다. 화면 자리는 **빠른 찾기 창(S-61) 찾기 탭 하나**다 — 내 경험에 「경험 찾기」 탭을 따로 두지 않는다(2026-11-09 PM: 찾기가 두 곳이라 헷갈린다 · 그 자리는 통계 S-83 · FE#274). 범위 제외: 의미 검색(임베딩) · 도구 · 기술 · 직무 태그(미결정 8) · 수행 주체로 거르기 · 검색 조건 저장 · MCP `search_experiences` 입력에 출처 상태 · 분류 더하기. 계약: [`contracts/experience-api.md`](contracts/experience-api.md) 「GET /api/experiences」
- `S-83` 내 경험에 **통계**를 두고 쌓인 경험을 한눈에 본다 — 우선순위 `P1`(2026-11-09 PM: 쌓인 블록이 홈 차곡이를 눌러야만 보여 있는 줄 몰랐다 · FE#274) · 레포 FE — 완료 조건: 내 경험(`/experience`)에서 타임라인과 나란히 연다(경험 찾기 탭이 있던 자리 — S-58). 연도별 **쌓인 블록**(S-28 과 같은 규칙 — 활동 시작 연도별로 경험 하나가 블록 하나 · 「기간 모름」 · 「확인 필요」 점선)과 활동 분류(S-57) · 출처 상태 · 역량별 경험 수가 보인다. 숫자는 모두 저장된 경험에서 계산한다 — 고정 값 · 예시 숫자로 채우지 않는다. 경험이 0개면 자료 넣기로 가는 안내만 보인다. AI 를 부르지 않는다. 연도가 많아져도 화면이 가로로 밀리지 않는다. 범위 제외: 시간 · 돈 합계(S-68) · 기간 바꿔 보기 · 내보내기. 새 계약 없음 — 지금 활동 · 경험 API 로 FE 가 계산한다(모자라면 계약 이슈로)

#### F-04 고치기

- 우선순위: `P0`
- 레포: FE · BE
- 의도: AI 가 나눈 결과는 틀릴 수 있다. 사람이 **누르거나 끌어다 놓는 정도로 쉽게** 바로잡을 수 있어야 「AI 가 정리하고 사람이 판단한다」가 된다. 모양 · 조작 방식은 담당이 만들어 보고 PM 이 화면을 보며 고친다
- `S-10` 활동(이름 · 기간)과 경험(내용 · 역량 · 수행 주체)을 고쳐 저장하면 새로고침해도 남는다 — 완료 조건: 세부에서 바로 고친다(다른 화면으로 가지 않는다). **본문을** 고친 경험의 출처 상태는 「내가 입력」이 되고, 원래 근거(발췌문)는 그대로 남는다. 수행 주체 · 역량만 고치면 출처 상태는 그대로다 — 「내가 입력」 본문은 근거가 되는데, 누가 했는지 · 어떤 역량인지 정한 것은 본문 글을 확인한 것이 아니다(2026-11-09 PM, ETC#249). 역량의 「AI 해석」 표시는 사용자가 **역량을** 고쳤을 때만 사라진다 — 본문 · 수행 주체만 고쳐서는 역량이 여전히 AI 가 붙인 것이다(2026-11-03, PM)
- `S-11` 경험을 직접 추가하거나 지운다 — 우선순위 `P0`(2026-11-02 `P1` 에서 올림: AI 가 채운 경험은 사용자의 기록이라, 더하고 지우는 것도 고치기만큼 기본이다) — 완료 조건: 활동 세부에서 바로 더하고 지운다(다른 화면으로 가지 않는다). 직접 더한 경험은 「내가 입력」이고 근거가 없다. 지운 경험은 새로고침해도 돌아오지 않는다
- `S-12` 경험을 다른 활동으로 옮긴다 — PC 는 끌어다 놓기, 끌기 어려운 환경(모바일)은 메뉴로도 — 우선순위 `P1` — 완료 조건: 옮긴 경험의 내용 · 근거 · 출처 상태는 그대로이고(묶음만 바뀐다), 새로고침해도 남는다
- `S-13` 활동 두 개를 하나로 합친다 — 우선순위 `P1` — 완료 조건: 남길 활동을 사용자가 고르고, 다른 활동의 경험이 모두 그쪽으로 옮겨진 뒤 빈 활동은 사라진다. 경험 · 근거는 하나도 잃지 않는다
- `S-44` 같은 활동의 자료를 또 넣으면(회고 다음에 README, 이력서 다음에 노트) AI 가 새 활동마다 **「기존 활동 X 와 같아 보여요」를 제안만** 하고, 사용자가 「붙이기 / 따로 두기」를 누른다 — 우선순위 `P1`(ETC#49 · 미결정 3 · 2026-11-05) — 완료 조건: 자동으로 합치지 않는다. 제안은 AI 해석으로 보이고, 같아 보이는 기존 활동의 이름 · 기간이 같이 보인다. 붙이면 S-13 합치기와 같은 결과다 — 기존 활동이 남고(이름 · 기간 그대로) 새 활동의 경험 · 근거가 하나도 빠지지 않고 옮겨진다. 따로 두면 제안이 사라지고 다시 나오지 않는다. 제안은 새로고침해도 남는다. 같아 보이는 활동이 없으면 아무것도 보이지 않는다(지금처럼 새 활동). 같은 사실이 두 자료에서 나와 경험이 겹치면 둘 다 남는다 — 사용자가 지우거나(S-11) 하나로 합친다(S-70). AI 에는 기존 활동의 **이름 · 기간만** 보낸다(경험 본문은 보내지 않는다)
- `S-70` 같은 활동의 경험 둘을 골라 **하나로 합친다** — 남길 쪽을 사용자가 고르면 지울 쪽 근거 · 보완이 남길 쪽으로 옮겨져 **경험 하나에 근거 둘**이 된다 — 우선순위 `P2`(ETC#114 · ETC#187 · 2026-11-06) · 레포 FE · BE — 완료 조건: AI 를 부르지 않는다. 근거 · 보완은 하나도 잃지 않고, 근거를 열면 두 원본 이름이 다 보인다(S-09). 남길 경험의 본문 · 역량 · 수행 주체 · 출처 상태는 그대로다(공개 프로필에 넣기 S-65 도 남길 쪽 값 — 지울 쪽만 골랐어도 공개되지 않는다). 지울 경험을 가리키던 지원 추천 · 초안 근거 · 빈칸 되묻기 · 확정 답변의 새 경험 후보 · 쓰인 지원(S-38)은 남길 경험을 가리킨다. 되돌리기는 없다(S-13 과 같다) — 합치기 전에 알린다. 범위 제외: 셋 이상 한 번에 · 다른 활동의 경험끼리(먼저 옮긴다 — S-12) · AI 가 겹치는 경험을 찾아 제안하기(ETC#114 큰 판 — S-44 의 「경험 본문은 보내지 않는다」를 뒤집는다)
- `S-71` 다시 쓸 경험을 **저장**해 두고 「저장한 것」으로 모아 본다 — 우선순위 `P2`(ETC#58 · 2026-11-06 PM: 스프린트 3 에 넣음) · 레포 FE · BE — 완료 조건: 활동 세부의 경험과 경험 찾기(S-58) 결과 줄에서 저장을 켜고 끈다(미결정 27). 저장했는지는 색만이 아니라 글자나 이름으로도 구분되고 새로고침해도 남는다. 저장은 경험의 본문 · 근거 · 출처 상태를 바꾸지 않는다. 경험 찾기와 빠른 찾기 창(S-61)에서 「저장한 것」으로 거른다 — 다른 거르기 · 낱말과 그리고로 묶인다. 경험을 옮기거나 활동을 합쳐도 저장은 따라가고, 경험을 합치면(S-70) 둘 중 하나라도 저장했으면 남길 경험이 저장된다. 범위 제외: 폴더 · 자주 찾는 태그(활동 분류 · 역량과 겹친다 — ETC#58) · 타임라인에서 거르기(활동 단위 화면이라 경험 찾기로 본다) · 외부 AI(MCP) · 공개 프로필 · 차곡이에 저장 여부 싣기. 계약: [`contracts/experience-api.md`](contracts/experience-api.md) 「PUT /api/experiences/{experienceId}/saved」
- `S-17` PC 타임라인에서 활동의 기간 띠 끝을 끌어 시작 · 끝 달을 고친다 — 우선순위 `P1`(2026-11-03 PM: 기간을 글자로 쳐서 고치는 건 「누르거나 끌어다 놓는 정도로 쉽게」에 못 미친다) — 완료 조건: 끄는 동안 바뀔 기간이 글자로 보이고, 놓으면 저장돼 타임라인 자리 · 띠가 바뀌고 새로고침해도 남는다. 실패하면 원래대로 돌리고 알린다. 끌기 어려운 환경(모바일) · 다른 해로 넘기기는 세부의 활동 고치기(S-10)로 한다

### R-02 계정과 사용 한도 — 공개 배포 전

> 목적: 심사위원이 테스트 계정으로 들어와 데모 흐름을 돌릴 수 있고, 모르는 사람이 LLM 호출을 마구 쓰지 못하게 한다([ADR-004](decisions/ADR-004-deploy.md)). 스프린트 1 흐름(R-01)이 돈 뒤에 붙인다.

#### F-05 로그인

- 우선순위: `P1`
- 레포: BE · FE
- `S-14` 로그인한 사람만 자료를 넣고 자기 경험을 본다 — 완료 조건: 테스트 계정으로 로그인해 R-01 흐름이 돈다. 다른 계정의 원본 · 활동 · 경험은 보이지 않는다. 가입 · 로그인 방식(아이디 · 비밀번호, 소셜 등)은 BE 담당이 정한다
- `S-15` 사용자별 하루 분석 횟수와 입력 크기에 한도가 있다 — 완료 조건: 한도를 넘으면 분석을 시작하지 않고 「오늘 분석 횟수를 다 썼어요」처럼 이유가 보인다. 한도 숫자는 설정값(미결정 질문 6). 분석을 쓰는 버튼 옆에는 작은 「분석 1회」 표시를 둔다. 한 줄에 그런 버튼이 여럿이면 표시는 한 번만 두고 나머지 버튼은 마우스를 올리면 알린다(FE#217 · 2026-11-07 PM). 빠진 사실에 답해 보완이 새로 생긴 뒤나 주체를 정한 뒤(S-76) 같은 문항의 초안을 다시 만들 때는 세지 않는다(S-77). 남은 횟수는 자료 넣기 창에 늘 보이고, 다른 화면에서는 3회 이하일 때만 경고한다(FE#183 · 2026-11-07 PM)

### R-03 지원 문항에 경험 꺼내 쓰기 — 스프린트 2

> 목표 흐름(데모 3 ~ 6): 지원 문항을 넣으면 → 쌓인 경험에서 맞는 것 2 ~ 3개가 근거 · 강조점 · 부족한 점과 함께 나오고 → 부족한 사실을 짧게 묻고 → 답이 **그 경험에** 「내가 입력」으로 쌓이고 → 다른 문항에서 같은 활동의 다른 경험과 방금 보완한 사실이 다시 쓰인다. SPEC §0 차별점(흐름 전체)의 본체이고, 기획이 「가장 강한 데모」로 꼽은 흐름이다(ETC#23).
>
> 데모 예: 기술 중심 부트캠프 문항 「기술적 문제를 해결한 경험」 → 「바꿔요」의 WebSocket 경험 추천 · 「직접 고친 부분은? 고친 뒤 어떻게 확인했나요?」 → 답이 그 경험에 쌓임 → 협업 중심 동아리 문항 「팀에서 갈등 · 일정을 조율한 경험」 → 같은 활동의 다른 경험(회고 · 일정)이 골라지고, 앞에서 답한 사실은 다시 묻지 않고 근거로 쓰인다.

| 지원 | 지원처 하나(이름은 선택)에 넣은 문항 여러 개의 묶음 — 실제 지원서 한 장. 동아리 · 비교과 · 대외활동(SW마에스트로 등) · 부트캠프 · 인턴 · 채용 모두 같은 모양이다(2026-11-03 PM). **화면 이름도 「지원」**(「지원서」 · 「지원활동」 아님 — 안에 공고 개요 · 요구사항 · 문항, 나중엔 이력서까지 담는 자리라 넓게. 「활동」과 헷갈리지 않게 — 2026-11-04 PM) |
| 지원 문항 | 지원 하나에 딸린 문항 텍스트 하나. 공고 일부를 같이 붙여도 된다. 문항은 사용자가 붙여 넣는다. 공고에 **적힌** 문항을 찾아 주기는 `P1`(붙여 넣은 글 S-30 · 링크 S-46), 문항을 **만들어** 주지는 않는다 |
| 요구사항 | AI 가 문항 · 공고를 쪼갠 「이 지원처가 보려는 것」 하나 — 도구(「Python · SQL」) 또는 능력 서술(「데이터 정합성 검증」). 문항 유형(성취 · 실패 · 협업 · 갈등 …)은 문항 쪽 해석이라 경험에 저장하지 않는다 |
| 추천 | 문항에 맞는 경험 하나 + 왜 맞는지 · 강조할 점 · 근거 · 부족한 점. 이유 · 강조점은 **AI 해석**이다 |
| 되묻기 | 문항에 필요한데 원본 · 보완에 없는 사실을 묻는 AI 의 짧은 질문. 어느 경험에 대한 질문인지가 붙는다 |
| 보완 | 되묻기에 사용자가 한 답. **그 경험에 딸린다**(질문 · 답 한 쌍) · 출처는 「내가 입력」(외부 AI 를 거친 답은 사용자가 확인한 뒤 — S-56). 경험 본문 · 근거 · 출처 상태는 바꾸지 않는다 |
| 문항 유형 | 문항이 묻는 꼴 하나(지원 동기 · 장단점 · 성취 · 문제 해결 · 협업 · 갈등 · 실패 · 성장 …) — 닫힌 목록(contracts README `questionType`). 매칭 때 AI 가 붙이고 사용자가 고친다. **문항의 속성**이라 경험에 저장하지 않는다(미결정 8 · 13) |
| 근거 점검 | 사용자가 쓴 답(초안을 고친 글이든 직접 쓴 글이든)을 문장마다 **원문 · 내가 입력 · 근거 없음 · 생각** 으로 칠하는 것(S-45). 맞춤법 · 다듬기 대신 이 서비스가 두는 「과장 점검」이다. 「근거 없음」은 거짓이라는 단정이 아니라 「확인해 주세요」다 |
| 확정 답변 | 사용자가 그 문항에 낼 글로 「확정」한 답(화면의 버튼은 「다 썼어요」 — FE#212) — **문항마다 최신 하나**(다시 확정하면 바뀐다). 초안을 고친 글이든 직접 쓴 글이든 같다. 새 경험 후보(S-48)와 예전 답변 다시 보기(S-43)의 재료다. 근거로 쓰지 않는다 |
| 지원처 종류 · 직무 | 지원에 붙는 선택 칸 두 개 — 동아리 · 비교과 · 대외활동 · 부트캠프 · 인턴 · 채용 / 백엔드 · 프론트엔드 · 디자인 · 기획 …(닫힌 목록, contracts README `organizationType` · `jobRole`). 사용자가 고른다. 비슷한 문항 · 답변을 고르는 데 쓴다 — 직무 분석이 아니다(미결정 17) |

#### F-06 문항 넣고 맞는 경험 추천받기

- 우선순위: `P0`
- 레포: FE · BE · AI
- 정해 둔 것: 매칭은 사용자 한 명의 경험 전부(본문 · 역량 · 수행 주체 · 근거 · 보완)를 LLM 에 후보로 넘기는 것으로 시작한다([ADR-003](decisions/ADR-003-stack-and-ai-boundary.md) — 임베딩 · pgvector 는 후보가 넘칠 때). 판정은 경험 본문 · 근거로 한다 — 역량 태그가 같다는 것만으로 고르지 않는다(태그를 AI 가 빠뜨려도 매칭이 무너지지 않게)
- `S-18` 지원처 이름(선택)과 문항을 **하나 이상** 넣으면(한 번에 여러 개) 문항마다 추천이 시작된다. 이미 넣은 지원에 문항을 더할 수 있다(2026-11-03 PM — 실제 지원서는 문항이 3 ~ 5개다) — 완료 조건: 지원 · 문항이 저장되고 문항마다 추천 상태(분석 중 → 완료 / 실패)가 보인다. 실패하면 그 문항에 실패했다는 것과 「다시 시도」가 보인다(정해진 결과로 대신 채우지 않는다). 분석 중에 새로고침해도 이어진다. 넣기 전에는 문항을 자유롭게 고치고 넣은 뒤엔 고치지 않는다(잘못 넣었으면 그 지원에 새로 더한다)
- `S-19` AI 가 문항을 요구사항 몇 개로 쪼개고, 요구사항마다 **근거 있음 / 일부 / 자료에서 확인 안 됨** 을 보여 준다 — 완료 조건: 「자료에서 확인 안 됨」이 「경험 없음」 · 「부족한 사람」처럼 읽히지 않는다(SPEC §0 제품 원칙). 점수 · 합격 가능성 같은 숫자를 보이지 않는다(범위 제외)
- `S-20` 맞는 경험을 **0 ~ 3개** 추천한다. 추천마다 왜 맞는지 · 강조할 점 · 근거 · 부족한 점이 보인다 — 완료 조건: 근거는 그 경험에 이미 있는 발췌문 · 보완만 쓴다(새 근거 · 수치를 지어내지 않는다 — 코드로 확인). 맞는 경험이 없으면 억지로 채우지 않고 0개다. 수행 주체가 팀 · 알 수 없음인 경험을 「내가 한 일」로 바꿔 말하지 않는다 — 내 몫이 불분명하면 그게 되묻기 거리다(S-22). 이유 · 강조점은 AI 해석으로 보이고, 추천된 경험에서 활동 세부(S-08)로 갈 수 있다
- `S-21` 넣었던 지원과 그 문항 · 추천을 목록에서 다시 연다 — 완료 조건: 새로고침해도 남는다. 한 지원 안에서 **같은 경험(또는 같은 활동)이 여러 문항에 추천되면 문항별로 어떤 강조점으로 쓰이는지 나란히** 보인다 — 막거나 경고하지 않는다. 대표 경험 1 ~ 2개를 문항마다 다른 각도로 쓰는 게 자연스럽다(2026-11-03 PM, 미결정 15). 강조점이 겹치는지는 사용자가 보고 고른다. 두 지원(또는 두 문항)의 추천을 오가거나 나란히 보며 같은 활동에서 다른 경험이 골라진 것을 볼 수 있다(배치는 FE 가 정한다)
- `S-26` 문항을 「자주 나오는 문항」 목록에서 골라 넣는다 — 우선순위 `P1` — 완료 조건: 지원 동기 · 장단점 · 협업 · 갈등 · 실패 · 성장 과정처럼 동아리 · 비교과 · 대외활동 · 채용에 자주 나오는 문항을 고르고, 고른 뒤 고치거나 직접 더해 넣는다. 목록은 **실제 공고 · 지원서에서 모은 문항**으로 채우고 어디서 모았는지(지원처 종류) 남긴다 — 지어낸 목록이 아니다(2026-11-03 PM). 목록은 FE 에 두고 AI 를 부르지 않는다
- `S-40` 「내가 넣었던 문항」을 「자주 나오는 문항」(S-26)과 같은 자리에서 골라 다시 넣는다 — 우선순위 `P1`(ETC#69 · 미결정 13 ①) — 완료 조건: 예전에 넣은 문항이 지원처 이름 · 문항 유형(S-41)과 함께 보이고, 고르면 새 지원의 문항 칸에 들어가 넣기 전에 고칠 수 있다. 글자가 같은 문항은 한 번만 보인다. AI 를 부르지 않는다(이미 저장돼 있다)
- `S-41` 매칭 결과에 **문항 유형** 하나가 같이 나오고, 사용자가 고친다 — 우선순위 `P1`(ETC#69 · 미결정 13 ②) — 완료 조건: 매칭(S-19)과 **같은 AI 호출**에서 붙는다(LLM 을 따로 부르지 않는다). AI 가 붙인 유형은 AI 해석으로, 사용자가 고친 유형은 그렇게 보인다. 고친 유형은 다시 시도해도 AI 가 덮어쓰지 않는다. 경험에는 저장하지 않는다. 맞는 유형이 없으면 「기타」다
- `S-42` 지원에 **지원처 종류 · 직무**를 고른다(둘 다 선택) — 우선순위 `P1`(ETC#69 · 미결정 17) — 완료 조건: 지원을 넣을 때 고르고, 넣은 뒤에도 바꾸거나 비운다. 직무가 없는 지원(동아리 · 서포터즈 등)은 비워 둔다. AI 가 채워 주기는 S-30(ETC#75). 추천 · 되묻기 결과는 이 칸으로 바뀌지 않는다(매칭 요청에 싣지 않는다). 직무는 답변 초안(S-27)에 직무 관련성 생각 문장의 단서로만 넘긴다 — 근거가 아니다(ETC#141)

#### F-07 부족한 사실 되묻기 · 보완

- 우선순위: `P0`
- 레포: FE · BE · AI
- `S-22` 추천과 함께, 문항에 필요한데 원본 · 보완에 없는 사실을 묻는 짧은 질문이 **문항 하나에 최대 3개** 나온다 — 완료 조건: 질문마다 어느 경험에 대한 것인지 붙고, 그 경험 · 문항에 맞게 구체적이다(「직접 고친 부분은?」 「고친 뒤 정상 동작을 어떻게 확인했나요?」 — 「더 자세히 알려 주세요」 같은 막연한 질문이 아니다). 원본 · 보완에 이미 있는 사실은 묻지 않는다. 답을 유도하는 수치를 넣지 않는다(「30% 줄이셨죠?」 같은 질문 금지 — S-05)
- `S-23` 질문에 짧게 답하면 그 경험의 **보완**으로 저장된다. 답은 선택이다 — 완료 조건: 활동 세부(S-08)의 그 경험에 질문 · 답이 「내가 입력」으로 보이고 새로고침해도 남는다. 경험 본문 · 근거 · 출처 상태(「원문에서 확인」 등)는 그대로다. 건너뛴 질문은 아무것도 저장하지 않고, 추천의 「자료에서 확인 안 됨」이 그대로 남는다(기록을 강요하지 않는다 — SPEC §0)
- `S-24` 보완을 고치거나 지운다 — 우선순위 `P1` — 완료 조건: 활동 세부에서 바로 고치고 지우며, 새로고침해도 남는다

#### F-08 보완한 사실 다시 쓰기

- 우선순위: `P0`
- 레포: AI · BE · FE
- `S-25` 다른 문항의 추천에서, 앞에서 답한 보완이 그 경험의 근거로 같이 쓰이고 「내가 입력」으로 보인다 — 완료 조건(데모 6): 문항 A 에서 답한 보완이 문항 B 추천의 근거로 나오고, B 에서 같은 사실을 다시 묻지 않는다. 같은 활동에서도 문항에 따라 다른 경험이 골라진다

#### F-09 답변 초안 — 우선순위 `P1`

- 우선순위: `P1` — R-03 의 `P0`(S-18 ~ S-23 · S-25)가 데모처럼 다 돈 뒤 시작한다(2026-11-03 PM)
- 레포: AI · BE · FE — ETC#26 · 근거 점검 ETC#74 · 새 경험 후보 ETC#67 · 작성 지침 · 구성 틀 ETC#68
- `S-27` 문항과 고른 경험으로 답변 초안을 만든다 — 완료 조건: **사실 문장(`FACT`)마다 어느 근거(원문 발췌) · 보완(내가 입력)에서 왔는지 표시**하고, 근거 · 보완이 받치지 않는 사실은 사실 문장으로 쓰지 않는다 — 풀어 쓴 문장은 「AI 보탬」, 모르는 값은 빈칸으로 구분한다(S-78 · S-05 · 범용 LLM 의 「자소서 써 줘」와 다른 점). 경험 · 근거 · 보완에 없는 수치 · 역할을 넣지 않는다. `TEAM` · `UNKNOWN` 경험을 「내가 한 일」로 쓰지 않는다. 최종 문장은 사람이 고친다(SPEC §0). 생각 문장(`OPINION`)은 연결 · 직무 관련성 · 포부 제안만 초안당 **최대 3개**, 근거 0개를 허용한다. 화면에 「AI 초안 · 생각」을 붙이고 카드에서 확인하게 해(경고 문구 · 맞아요) 사실과 구분한다. 숫자 · 새 사실 · 감정 지어내기 · 칭찬 · 의미 단정은 금지하며, `TEAM` · `UNKNOWN` 일을 내 일로 바꾸지 않는다. 숫자와 개수는 코드가 막는다. 자료에 있는 배운 점 · 감정은 근거를 붙인 사실로 쓴다. S-34 의 생각 · 계기 기록은 초안 재료나 추천 근거로 쓰지 않는다. 텍스트 복사는 생각 문장도 포함하되 화면의 표시 · 근거 칩은 복사하지 않는다. 받치는 것은 원본에서 찾은 발췌(원문) · 보완 · 직접 넣거나 고친 경험 본문(내가 입력)이다 — 원본에서 못 찾은 발췌는 받치지 않는다(S-45 와 같은 기준). 받칠 게 없어 쓰지 않은 것(확인한 방법 · 느낀 점 …)은 지어내지 않고 「자료에 없어 쓰지 않았어요」로 따로 보인다. 문장 속 숫자가 받치는 근거 · 보완에 없으면 **코드가** 막는다. 초안은 문항마다 최신 하나 — 다시 만들면 바뀐다(ETC#102 · 2026-11-05)
  - **빠진 사실에 답하고 다시 만들기**(ETC#139 · 2026-11-05): 쓰지 않은 것은 초안 하나에 **최대 5개**, 어느 경험의 빈칸인지와 짧은 질문을 붙인다. 추천의 되묻기(S-22, 최대 3개)와 별개다. 질문은 S-22 처럼 구체적으로 묻고, 이미 있는 사실을 다시 묻거나 수치 · 역할을 유도하지 않는다. 답은 선택이고 그 경험의 **보완**(질문 · 답, 「내가 입력」)으로 쌓인다(S-23) — 경험 본문 · 근거 · 출처 상태는 그대로, 다음 문항에서도 재사용한다(S-25). 경험에 붙지 않는 빈칸(지원 동기 등)은 질문 · 경험을 붙이지 않고 사용자가 직접 쓸 거리로만 보인다(보완으로 저장하지 않는다). 답해도 초안은 그대로이며, **사용자가 다시 만들기를 누를 때** 최신 보완으로 다시 쓴다(분석 1회). 건너뛰어도 초안을 쓰고 복사할 수 있다. 저장 · 다시 만들기 실패는 오류와 다시 시도를 보인다.
  - **추천의 강조점을 초안에**(ETC#141 · 2026-11-05): 같은 경험이라도 지원처 · 문항마다 앞세우는 사실이 달라지게, 그 문항 추천의 요구사항 · 이유 · 강조점 · 부족한 점과 지원의 직무(S-42)를 초안 재료로 넘긴다(LLM 을 더 부르지 않는다). 모두 AI 해석이라 **근거가 아니다** — 문장 순서 · 비중 · 빠진 것 고르기에만 쓰고, 강조점에 쓸 사실이 근거 · 보완 · 본문에 없으면 쓰지 않고 「자료에 없어 쓰지 않았어요」로 보인다. 화면은 바뀌지 않는다. 사용자가 강조점을 고치는 화면은 범위 밖이다.
- `S-43` 사용자가 **확정한 답변**을 비슷한 문항에서 **참고로** 다시 보인다 — 우선순위 `P1`(ETC#69 · 미결정 14 다) — 확정 답변(S-48 · ETC#67)이 생긴 뒤 — 완료 조건: 같은 문항 유형(S-41) → 같은 직무 → 같은 지원처 종류(S-42) 순으로 가까운 것부터 최대 5개 보이고, 어느 지원 · 문항의 답변인지 붙는다. 유형이 달라도 직무나 종류가 같으면 뒤쪽에 보인다. 값이 없거나 「기타」면 같다고 보지 않는다(ETC#109 · 2026-11-05 기본값). **근거로 쓰지 않는다** — 초안(S-27)의 근거 · 매칭 후보에 넣지 않는다(지원 동기엔 그 지원처 이야기가 섞인다). AI 를 부르지 않는다. 없으면 아무것도 보이지 않는다. 계약: [`contracts/question-api.md`](contracts/question-api.md) 「비슷한 확정 답변」
- `S-45` 사용자가 쓴 답을 **근거 점검**한다 — 문장마다 원문 발췌(원문) · 보완이나 직접 넣은 경험(내가 입력)이 받치는지, 받치는 게 없는지(근거 없음), 사실이 아닌 생각 · 포부 · 이어 주는 문장인지(생각)를 칠한다 — 우선순위 `P1`(ETC#74 · 2026-11-05 PM) — 완료 조건: 대조 대상은 그 사용자의 **경험 전부**(본문 · 원본에서 찾은 근거 · 보완 — 추천된 경험만이 아니다). 근거 없는 문장은 눈에 띄게 칠하고 「지우거나, 사실이면 근거를 더해 주세요」를 보인다 — 거짓이라고 단정하지 않는다. 원문 · 내가 입력 문장은 어느 근거 · 보완인지 열어 본다. 문장 속 숫자가 받치는 근거 · 보완에 없으면 **코드가** 근거 없음으로 돌린다(S-04 원문 대조 코드를 다시 쓴다 — 「만족도가 30% 올랐다」를 근거 있음으로 두지 않는다). `TEAM` · `UNKNOWN` 경험을 「내가 했다」로 쓴 문장은 근거 없음이다. 「생각」은 AI 해석으로 보이고 칠하지 않는다 — 숫자가 든 문장은 생각이 될 수 없다. 결과는 **문항마다 최신 하나** 저장해 새로고침해도 남고, 글을 고치면 다시 점검한다(분석 1회로 센다). 점검이 실패하면 오류 · 다시 시도를 보인다(정해진 결과로 칠하지 않는다). 글은 고치지 않는다 — 고치는 건 사람이다(SPEC §0)
- `S-48` 사용자가 그 문항의 답을 **확정**하면, 글에서 **사용자가 새로 쓴 사실 문장**만 「새 경험 후보」로 보이고 사용자가 확인하면 고른 활동의 경험으로 저장한다 — 우선순위 `P1`(ETC#67 · 미결정 14 가 · 2026-11-05) — 완료 조건: 확정 답변은 문항마다 최신 하나다. 확정(「다 썼어요」)은 **저장만** 하고 분석 횟수를 쓰지 않는다 — 저장된 걸 보이고, 바로 아래 「새 경험 후보 찾기 (분석 1회)」를 누르면 후보를 찾는다(ETC#250 · 2026-11-09 PM — 저장만 하려 해도 분석을 쓰고, 같은 글로 다시 누르면 또 쓰고 후보가 지워져서. 따로 버튼만 두면 아무도 안 눌러 한 줄로 바로 아래에). 한도를 다 썼으면 후보 찾기만 오류 · 다시 시도. 같은 글로 이미 찾았으면 다시 찾지 않는다. 후보는 지난 일 · 결과를 말하면서 그 사용자의 경험 · 근거 · 보완이 받치지 않는 문장이다 — **근거가 없다는 것만으로 고르지 않는다.** 빼는 것: 생각 · 동기 · 포부 · 이어 주는 말(생각 · 계기 기록 ETC#33 의 몫) · 자기 칭찬 · 포장(「누구보다 헌신적으로」 — S-05) · 기존 자료와 어긋나는 문장(팀이 한 일을 「제가」로 — S-45 에서 근거 없음) · **저장된 초안과 글자가 같은 문장**(AI 제안을 복사했거나 근거가 지워진 초안 문장 — 코드가 뺀다) · 그 문항에서 전에 「저장 안 함」 한 문장(코드가 뺀다). 후보마다 원래 문장 · 경험 문장(「~했다」 — 원래 문장에 없는 사실 · 수치를 더하지 않는다, 숫자는 코드가 대조) · 수행 주체 · 붙일 활동 제안(AI 해석)이 보이고, 사용자가 고쳐 「경험으로 저장」하거나 「저장 안 함」을 누른다. 저절로 저장하지 않는다. 붙일 활동은 기존 활동 중에서 고른다(새 활동 만들기는 범위 밖). 저장한 경험은 「내가 입력」이고 출처 「내가 쓴 지원서 — 지원처 · 문항」이 붙어 「원문에서 확인」과 구분된다. 다른 경험과 같은 급으로 추천 · 되묻기 · 초안 · 근거 점검 · MCP 에 쓰인다 — 다음에 같은 문장을 확정하면 그 경험이 받치므로 다시 후보가 되지 않는다. 후보가 없으면 「새로 쓴 사실이 없어요」. 찾기가 실패하면 오류 · 다시 시도(정해진 후보로 채우지 않는다). **다른 글로** 다시 확정하면 아직 정하지 않은 후보는 사라지고 저장한 경험은 남는다 — 같은 글로 다시 확정하면 아무것도 바뀌지 않는다(후보 그대로). 계약: [`contracts/question-api.md`](contracts/question-api.md) 「확정 답변」
- `S-72` 쓰는 중인 답이 **자동으로 저장**되어 새로고침 · 다른 기기에서도 이어 쓴다 — 우선순위 `P1`(2026-11-07 PM · FE#212) · 레포 FE · BE — 완료 조건: 문항마다 임시 글 하나다. 쓰다 멈추면 저장되고 저장 상태가 보이며, 실패하면 글을 지우지 않고 오류 · 다시 시도를 보인다. 임시 글은 **확정 답변이 아니다** — 새 경험 후보(S-48) · 예전 답변 다시 보기(S-43) · 지침 제안(S-51)에 쓰지 않고, AI 를 부르지 않아 분석 횟수를 세지 않는다. 「다 썼어요」를 눌러야 확정이다.
- `S-49` 사용자가 들은 작성법(자소서 작성법 영상 · 멘토 · 현직자 피드백)을 **작성 지침**으로 쌓고, 켜 둔 지침으로 답변 초안(S-27)의 결을 맞춘다 — 우선순위 `P1`(ETC#68 · 미결정 16 · 2026-11-05) — 완료 조건: 요점이나 자막을 붙여 넣으면(출처 — 어느 영상 · 누구의 피드백 — 는 적어도 되고 비워도 된다 · 2026-11-09 PM · BE#138) AI 가 **붙여 넣은 글에 있는 것만** 지침 한 줄씩으로 정리한다 — 우리가 일반론을 더하지 않는다. 사용자가 줄을 고치거나 빼고 저장한다 — 저절로 저장하지 않는다. 한 줄씩 직접 써서 저장해도 된다. 정리는 분석 1회로 세고, 실패하면 오류 · 다시 시도(정해진 지침으로 채우지 않는다). 지침은 0개에서 시작한다 — 우리가 미리 넣어 두지 않는다. 지침마다 켜고 끈다(켠 것 최대 10개). 초안을 만들 때 켠 지침을 싣고, 초안 옆에 **「적용한 지침」**(지침 · 출처 — 출처가 없으면 지침만)과 이번엔 반영하지 못한 지침 · 이유 한 줄이 보인다 — 반영했는지는 AI 해석이다. **지침은 문체 · 구성 · 강조만 바꾼다 — 근거 규칙이 우선이다**: 「수치를 꼭 넣어라」가 있어도 근거에 없는 수치를 만들지 않고 「반영 못 함 — 자료에 수치가 없어요」로 보인다(S-05 · S-27). 숫자 대조 · 생각 문장 규칙은 지침과 상관없이 그대로다. 지침은 경험과 따로 두고 추천 · 근거 점검 · 새 경험 후보 · MCP 에 쓰지 않는다. 지침끼리 부딪치면 사용자가 끈다(AI 가 고르지 않는다). 지침을 고치거나 지워도 이미 만든 초안의 「적용한 지침」은 만들 때 그대로다. 계약: [`contracts/guideline-api.md`](contracts/guideline-api.md)
- `S-50` 초안을 만들 때 **구성 틀** 하나를 고른다 — 우선순위 `P1`(ETC#68 · 미결정 16 ① · 2026-11-05) — 완료 조건: 틀은 우리가 준비한 공개 작성 기법 3개(STAR · CARL · PREP — 단계 · 출처는 contracts README `draftFrame`)와 「틀 없이」다. 문항 유형(S-41)으로 하나가 미리 골라져 있고(코드 표 — LLM 을 따로 부르지 않는다. - `S-51` 사용자가 초안을 고쳐 확정하면(S-48) 차곡이가 「이번에 고친 걸 지침으로 남길까요?」를 묻는다 — 우선순위 `P1`(ETC#68 · 미결정 16 ② · 2026-11-05) — S-49 · 차곡이(S-31) · 확정 답변(S-48)이 선 뒤 계약을 정한다 — 완료 조건(기본값): 저절로 저장하지 않는다. 차곡이 쓰기 도구(지침 저장 — MCP 와 같은 도구 목록)로 사용자가 지침 줄을 고쳐 확인한 뒤에 저장하고, 출처는 「내가 고친 초안 — 지원처 · 문항」이다. 고친 사실(내용)은 지침이 아니다 — 새 사실은 S-48 의 몫이다

- `S-73` 지원처 이름을 넣은 뒤에도 고친다 — 우선순위 `P1` · 레포 FE · BE — 완료 조건: 지원 화면 제목을 눌러 그 자리에서 고치고 새로고침해도 남는다. 비우면 「지원처 없음」과 같이 보인다. 추천은 다시 돌지 않는다
- `S-74` 활동 세부 · 근거의 **자료 이름을 누르면 그 자료의 원문**을 읽는다 — 우선순위 `P1` · 레포 FE · BE — 완료 조건: 읽기 전용이고 분석 횟수를 쓰지 않는다. 파일은 뽑아 저장한 글자로 보인다(PDF · PPTX 의 모양은 보이지 않는다). 근거에서 열면 그 발췌 위치로 간다. 공개 프로필에서는 열리지 않는다
- `S-75` 초안이 **활동 나열이 아니라 글**이 된다 — 우선순위 `P0` · 레포 AI · BE · FE — 완료 조건: 고른 경험과 같은 활동의 나머지 경험(최대 12개)도 재료로 쓴다. 첫째로 고른 경험의 활동을 먼저 채운다 — 둘째 · 셋째의 활동은 각 2개까지(그 활동 하나와 문항이 딱 맞을 때 재료가 흩어지지 않게). 초안 만들기에 「같은 활동의 다른 경험도 뒷받침 재료로 쓰기」가 보이고(기본 켬), 끄면 고른 경험만 쓰며 짧거나 부실할 수 있다고 알린다. 보조 재료에서 온 문장도 근거로 어느 자료에서 왔는지 보이고, 보조 재료 경험에 빠진 사실도 물을 수 있다(2026-11-08 PM). 고른 경험이 뼈대다. 첫 문장은 문항에 답하는 주제문, 대표 경험 하나를 깊게, 나머지는 그것을 뒷받침하는 한두 문장, 끝은 문항으로 잇는다. 경험마다 같은 무게로 한 문장씩 늘어놓지 않는다. 채점(scripts/eval_draft.py)에 「나열이 아닌가」를 더한다
- `S-76` 활동 단위로 **「이 활동의 일은 내가 했어요」** 를 한 번에 정한다 — 우선순위 `P0` · 레포 FE · BE — 완료 조건: 그 활동의 `UNKNOWN` 경험만 고른 값(`ME` · `TEAM`)으로 바뀌고 `ME` · `TEAM` 으로 이미 정한 경험은 그대로다. 출처 상태는 바뀌지 않는다. 몇 개가 바뀌었는지 보인다. 분석 횟수를 쓰지 않는다. 활동 세부에서 쓴다(초안 카드는 그 문장의 근거 경험만 정한다 — S-79, 2026-11-09)
- `S-77` 문항에 **목표 글자 수**를 둔다(선택) — 우선순위 `P0` · 레포 FE · BE · AI — 완료 조건: 100 ~ 5,000자. 문항 글에 「500자」처럼 있으면 미리 채워지고 사용자가 고친다(코드 — LLM 을 부르지 않는다). 초안은 목표의 80 ~ 100% 를 노린다. 받칠 재료로 못 채우면 지어내지 않고 빈칸으로 남기며, 지금 글자 수와 목표가 보인다. 고른 경험의 근거 글자 수가 목표의 절반이 안 되면 만들기 전에 알리되 막지 않는다. 빠진 사실에 답해 보완이 새로 생긴 뒤 다시 만들면 분석 횟수를 쓰지 않는다. 초안을 만든 뒤 그 재료 경험의 주체를 정하거나 바꿨을 때(S-76 · S-79 — AI 보탬의 「누가 했는지 확인해 주세요」)도 같다(2026-11-08 · 바꿈 포함 2026-11-09). 주체는 경험마다 처음 한 번만 센다. 초안은 재료 범위에서만 목표를 노려 정확한 글자 수를 맞추지 않는다 — 목표보다 짧으면 「자료에 있는 내용으로만 써서 목표보다 짧을 수 있어요」를 보인다
- `S-78` 초안 문장을 **세 등급**으로 나눈다 — 우선순위 `P0` · 레포 AI · BE · FE — 완료 조건: **근거**(`FACT`) · **AI 보탬**(`ELABORATED` — 받치는 사실의 맥락 · 연결을 풀어 쓰거나 주체가 확인되지 않은 일을 「제가」로 쓴 문장. 뼈대가 된 근거 · 보완 1개 이상을 붙이고 왜 확인이 필요한지 한 줄을 붙인다) · **빈칸**(`[결과]` 같은 자리 표시 — 수치 · 성과 · 직책처럼 사용자만 아는 값. `omitted` 항목과 짝을 이룬다). 숫자는 받치는 글에 있어야 하고(코드가 막는다), `TEAM` 일을 내 일로 쓰지 않는다. 새 사실 · 칭찬 · 감정 · 기술 이름을 더하지 않는다. 빈칸이 남은 채 복사하면 몇 개 남았는지 알린다. `OPINION` 은 그대로다. `ELABORATED` 는 S-48 새 경험 후보로 저절로 올리지 않는다
- `S-79` 초안을 **글 하나로 놓고 표시를 눌러 고친다**(Grammarly 같은 교정 화면) — 우선순위 `P0` · 레포 FE — 완료 조건: 「답변 초안」 블록 대신 답칸에 초안이 들어간다. 근거 문장은 조용히 두고, AI 보탬은 밑줄, 빈칸은 강조, 생각 문장은 점선 밑줄로 색에만 기대지 않게 구분한다. 표시를 누르면 카드가 떠서 근거 발췌 · 왜 확인이 필요한지와 「맞아요 · 고치기 · 빼기」가 보인다. 빈칸은 카드에서 답하면 글자리가 채워지고 보완으로 쌓인다(S-23). 주체 확인은 카드에서 **그 문장의 근거 경험만** 정한다 — 근거 경험이 여럿이면 경험마다 고르고, 같은 경험을 쓰는 다른 문장 · 문항도 같이 바뀐다. 출처 상태는 바뀌지 않는다(S-10 · 2026-11-09 PM, ETC#249). 위에는 「확인할 곳 N」만 둔다. 보기 · 고치기 상태를 나누지 않는다 — 답칸에서 바로 고치고, 고친 문장도 원래 문장과 절반 이상 닮았으면 표시 · 카드가 남는다(「고침」 — 원래 문장 · 근거를 같이 보인다). 많이 바꿨거나 새로 쓴 문장은 내 글이라 표시가 없고 근거 점검(S-45)이 본다. 고친 문장의 숫자가 원래와 다르거나 채운 빈칸 값을 고쳤으면 「확인할 곳」에 센다. 빈칸은 눌러서만 답한다. 직접 지운 문장은 편집이고 「빼기」만 저장한다(2026-11-09 PM · FE#283). 모바일은 하단 시트다. 키보드로 다음 표시로 옮겨 다닌다. 표시는 화면에만 있고 복사되지 않는다 카드 머리줄 왼쪽은 누가 쓴 문장인지(「내가 쓴 문장」 · 「AI 초안 · 근거」 · 「AI 초안 · 보탬」 · 「AI 초안 · 생각」 — 초안 생각과 근거 점검의 생각은 같은 범주라 같은 이름), 오른쪽은 근거 점검(S-45) 꼬리표다(「점검 ✓ 원문」 · 「점검 ✓ 내가 입력」 · 「점검 · 근거 없음」 · 「점검 · 생각」 · 「고치기 전 결과」 — 점검 전이면 없다). 근거는 초안 근거와 점검 근거를 한 목록으로 보이고, 판정이 AI 해석임을 카드에 한 줄 밝힌다. 근거 점검 결과는 답칸 문장에 붙고 내가 쓴 문장도 점검 뒤 블록이 된다 — 근거 없음은 칠하고 「확인할 곳」에 센다(칠하기는 판정을, 세기는 확인을 따른다). 화면에서만 누른 맞아요는 문장 글로 기억하고, 다 쓴 답에 글자 그대로 있는 문장은 확인 끝으로 본다 — 고치지 않은 AI 보탬 · 생각은 맞아요로 확인한다. 같은 글은 다시 점검하지 않는다(2026-11-10 · FE#307 · FE#317 · FE#319).
- `S-80` 경험 · 활동 · 지원서 답의 **수정 이력**을 보고 고른 때로 되돌린다 — 우선순위 `P1`(2026-11-07 · [ADR-013](decisions/ADR-013-revision-history.md)) · 레포 FE · BE — 완료 조건: 입구는 둘이다 — 헤더의 저장 상태(시안 6 「모두 저장됨」, 구분선 뒤)를 누르면 「최근 수정」이 경험 · 활동 · 답을 섞어 시간순으로 열리고(좁은 화면은 아이콘 · 하단 시트), 경험 · 활동 메뉴와 답칸 줄의 「수정 이력」은 그 항목만 보인다. 줄을 누르면 그 항목으로 간다. 경험은 본문 · 수행 주체 · 역량 · 출처 상태, 활동은 이름 · 기간, 답은 글 전체를 기록한다. 답은 「다 썼어요」, 초안으로 덮어쓰기, 되돌리기 때만 남기고 자동 저장(S-72)은 남기지 않는다. 언제 · 누가(나 / 외부 AI) · 무엇이 바뀌었나가 보이고, 외부 AI 변경도 같은 목록에 든다. 되돌리기는 지난 이력을 지우지 않고 새 기록을 더한다. 경험을 되돌리면 그때의 출처 상태로 돌아간다. 기록은 지우지 않고 모두 남기며 목록은 「더 보기」로 넘긴다. 분석 횟수를 쓰지 않는다. 지운 경험 · 합치기의 복구는 범위 밖이다
- `S-81` 어딘가에서 본 자소서를 붙여 넣으면 **구조만 뽑아 「내 구조」로 저장**한다 — 우선순위 `P1`(ETC#234 · 2026-11-07) · 레포 FE · BE · AI — 완료 조건: 작성 지침 화면에서 글을 붙여 넣으면 AI 가 구조 이름 · 단계 3 ~ 6개 · 맞는 문항 유형을 정리하고 사용자가 고쳐 저장한다. **원문은 분석 뒤 저장하지 않고**, 출처 칸도 없다. 구조에는 그 글의 문장 · 고유명사 · 수치를 남기지 않는다. 초안의 구성 틀(S-50)에서 내 구조를 고른다 — 구조는 순서일 뿐 근거가 아니다. 분석 1회를 쓴다. 사람당 20개까지
- `S-82` 기본 구성 틀에 **활동 나열을 막는 구조 카드**를 더한다 — 우선순위 `P1`(ETC#234 · 2026-11-07) · 레포 ETC · AI · FE — 완료 조건: 팀원이 사용자처럼 몇 편만 읽고 손으로 정리한 구조를 문항 유형별로 둔다(`draftFrame` 값 추가). 원문은 레포 · 서비스에 넣지 않고, 개별 글의 출처는 적지 않는다. 크롤링 · 대량 수집은 하지 않는다

#### F-10 입구 하나(차곡이)

- 레포: FE · BE · AI — 결정: [ADR-007](decisions/ADR-007-chagok-entrance-agent.md) · 계약(S-28 ~ S-30 · S-46): [`contracts/entrance-api.md`](contracts/entrance-api.md) — 셋 다 저장 없이 바로 답한다(ETC#118 · ETC#126)
- `S-28` 홈 입력에 넣은 글을 AI 가 **자료(쌓기) / 문항 · 공고(지원)** 로 가르고 이미 있는 흐름(S-01 · S-18)으로 넘긴다 — 우선순위 `P0` — 완료 조건: 애매하면 「자료로 쌓을까요, 지원으로 만들까요?」를 묻는다. 입력칸 위 모드(꺼내기 / 쌓기)로 사용자가 직접 정할 수 있고, 잘못 갈렸으면 한 번에 다른 쪽으로 보낸다. 가르기가 실패하면 묻는다(정해진 결과로 대신 채우지 않는다). 파일을 올리면 쌓기다
  - 홈(`/`)은 시안 6의 입력 · 「이어서」 카드로 구성하고 타임라인은 내 경험(`/experience`)에서 연다(2026-11-05 PM · FE#86). 쌓기 · 파일은 홈에서 보내기를 누르면 자료를 저장하고 분석을 시작한다. 외부 AI 전송 안내(S-16)는 보내기 전에 보이고, 분석 중 · 실패 · 다시 시도는 S-02를 따른다. 꺼내기에서 자료/지원으로 갈렸을 때는 기존 입력 화면에 글을 채워 넘기고 사용자가 그 화면에서 저장한다.
  - 「이어서」는 실제 데이터로 **최근 지원 / 마지막으로 연 활동 / 1년 전 이맘때 경험** 세 칸이다. 최근 지원은 만든 시각이 최신인 지원, 마지막 활동은 같은 브라우저 탭·계정에서 마지막으로 연 활동이다. 작년 이맘때는 활동 기간이 작년 같은 달과 겹치는 경험을 보여 준다(여럿이면 시작이 최근인 활동). 월을 모르는 기간으로 특정 달의 경험을 추측하지 않는다. 데이터가 없으면 새 지원 입력이나 내 경험 보기로 연결하고, 조회 실패는 오류·다시 시도로 보인다. 「작성 중」·「어제 쌓임」 같은 정보는 데이터가 뒷받침할 때만 쓴다.
  - 캐릭터를 누르면 **쌓인 블록**을 연다. 활동 시작 연도별로 경험 하나가 블록 하나이며, 시작을 모르면 「기간 모름」으로 묶는다. 「확인 필요」 경험은 점선으로 구분한다. 색은 장식이고 새로운 활동 분류를 뜻하지 않는다. 총 경험 수와 확인할 경험 수는 저장된 자료에서 계산한다. 같은 블록을 내 경험 통계(S-83)에서도 본다.
  - 모드별 **예시 칩**은 입력칸만 채우고 자동으로 보내거나 저장하지 않는다. **모델 메뉴**는 시안처럼 현재 제공되는 「기본 모델」 하나를 선택·확인한다. 「내 API 키로」는 아직 제공하지 않는 항목으로 표시한다. 실제 모델 변경·BYOK는 ETC#28의 별도 범위다.

- `S-30` 붙여 넣은 문항 · 공고에서 **지원처 이름 · 종류 · 직무 · 문항**을 AI 가 나눠 채우고 사용자가 고친 뒤 넣는다 — 칸을 손으로 채우지 않는다 — 우선순위 `P1`(ETC#75) — 완료 조건: 문항은 공고에 **적힌** 것만(만들지 않는다 — R-03 범위 제외). 미결정 12(공고 링크 읽기)와 같은 기능이고, 종류 · 직무는 미결정 17 의 선택 칸이다
- `S-46` 공고 **링크** 하나를 붙이면 그 페이지를 한 번 읽어 S-30 과 같이 지원 칸을 채우고, **원문 링크를 지원에 남긴다** — 우선순위 `P1`(ETC#65 · 미결정 12) — 완료 조건: 사용자가 준 링크 하나를 **그때 한 번만** 읽고 본문은 저장하지 않는다 — 모아 두거나 다른 사용자에게 보이지 않는다(공고 DB 아님). robots.txt 가 막거나 · 못 받거나 · 글이 거의 없으면(JS 로 그리는 페이지 · 포스터 이미지) 정해진 결과로 채우지 않고 「이 링크는 읽지 못했어요 — 공고 본문을 붙여 넣어 주세요」로 돌아간다(왜 못 읽었는지 한 줄). 링크에서 문항을 못 찾았으면 그렇게 보이고 본문을 붙여 넣어 다시 찾을 수 있다. 채운 칸은 S-30 과 같이 「AI 가 채움」이고 사용자가 고친 뒤 넣는다. 지원 화면에서 원문 링크를 연다. 홈 입력에 링크만 넣어도 같다. **공고 요약은 만들지 않는다** — 원문 링크가 대신한다(2026-11-05 PM). 시험: 사람인 · 잡코리아 · 원티드 · 링커리어 · SW마에스트로 · 학교 비교과 공지 · 회사 채용 페이지 링크로 읽힌 수를 남긴다
- `S-31` 차곡이가 **도구**로 한 입력을 여러 단계로 처리한다(예: 질문 → 경험 찾기 → 「이걸로 지원을 만들까요?」 → 지원 만들기) — 우선순위 `P1`(ETC#99) — 완료 조건: 단계마다 무엇을 하는지 보인다. 저장 · 변경(자료 넣기 · 지원 만들기 · 보완 저장)은 사용자가 확인한 뒤에만 한다. 도구 목록은 MCP(S-32)와 같다
  - 1차(ETC#132, 기본값): 입구는 지원 화면의 차곡이 패널(부탁 입력 · 미리 정한 부탁 버튼). 차곡이는 읽기 도구로 찾은 경험을 근거 카드로 보이고, 쓰기(지원 만들기 · 자료 넣기)는 「만들까요?」로 멈춰 사용자가 누르면 실행하고 그 일은 끝난다. 실패하면 오류와 「다시 시도」. 근거 점검 · 초안 · 보완 저장 도구는 S-45 · S-27 뒤 — [`chagok-api.md`](contracts/chagok-api.md)
- `S-47` AI 작업이 도는 동안 사용자는 다른 화면을 평소처럼 쓰고, **어느 화면에서든 진행 중인 일**이 보이며 끝나면 「소식」에 뜬다 — 우선순위 `P1`(ETC#147) — 완료 조건: 자료 분석 · 추천 · 근거 점검 · 초안 · 차곡이 일이 대상이다. 화면을 옮기거나 새로고침해도 진행 중인 일이 사라지지 않는다. 누르면 그 자리(자료 · 문항 · 차곡이 일)로 간다. 실패한 일도 소식에 뜨고 거기서 다시 시도할 수 있다. 읽음은 계정 단위라 다른 기기에서도 읽은 것으로 보인다. 자리 · 모양은 시안 6 을 보고 FE 가 고른다(ADR-002). 계약: [`contracts/work-api.md`](contracts/work-api.md)
  - 차곡이 일은 한 번에 하나다(S-31). 일하는 중에 새 부탁을 하면 오류로 끝내지 않고 **「그만두고 새로 시작」 / 「기다리기」** 를 묻는다 — 쓴 글은 지우지 않는다. 동시 실행은 제출 전에 하지 않는다. 줄 세우기는 미결정 22
- `S-61` 어느 화면에서든 **Ctrl K**(Mac 은 ⌘K)로 **빠른 찾기 창** 하나를 열어 경험 찾기 · 차곡이에게 묻기 · 바로가기를 오간다 — 우선순위 `P1`(ETC#77 · 2026-11-05 PM: P2 → P1 · 2026-11-06 PM: 찾기 탭 거르기 칩 추가) · 레포 FE — 완료 조건: 창은 지금 화면 위에 뜨고 Esc 나 바깥을 누르면 닫혀 원래 화면 그대로다. 키보드가 없는 폭(모바일)에서는 화면에 늘 보이는 버튼으로 연다. 창 안은 **탭 셋** — 탭이 기본이고 맨 앞 글자는 아는 사람만 쓰는 덤이다(`?` 로 시작하면 묻기, `>` 로 시작하면 바로가기, 그 밖은 찾기). ① **찾기** — S-58 과 **같은 검색**(같은 낱말이면 같은 결과)이고 결과 한 줄도 S-58 과 같이 경험 하나인데, 창 안의 줄은 시안처럼 분류 점 · 본문 · 활동 이름만 보이고 기간 · 수행 주체 · 출처 상태 · 역량은 오른쪽 미리 보기에 있다. 「확인 필요」만 줄에도 글자로 붙는다(FE#210 · 2026-11-07 PM). 미리 보기가 없는 좁은 폭은 고르면 활동 세부에서 본다. 고르면 창이 닫히고 그 활동의 세부(S-08)가 열린다. AI 를 부르지 않는다. 찾기 탭에서는 칩으로 **분류 · 역량 · 연도 · 확인 필요만**을 거른다 — S-58 과 같은 조건이고 낱말과 그리고로 묶인다(「저장한 것」은 S-71 이 들어올 때 더한다). S-58 의 자리가 이 탭이라 「검색에서 더 보기」는 없다 — 결과가 많으면 창 안에서 더 보고, 몇 개 중 몇 개인지와 더 좁히라는 안내가 보인다(2026-11-09 PM · FE#274). ② **묻기** — 한 줄 질문을 꺼내기(S-29)로 보내 **근거 달린 경험 0 ~ 3개**를 창 안에서 보인다. 분석 1회를 세므로(S-15) 칠 때마다가 아니라 **보낼 때만** 부른다. 0개면 「쌓인 자료에서 찾지 못했어요」, 실패하면 오류 · 다시 시도, 문항처럼 보이면 「지원으로 만들까요?」(S-29 그대로). ③ **바로가기** — 자료 넣기 · 새 지원 · 내 경험 같은 **화면으로 옮겨 가기만** 한다 — 창에서 저장 · 분석을 시작하지 않는다. 범위 제외: 차곡이 일(S-31 — 도구 · 확인 카드는 차곡이 패널) · 단축키 바꾸기 · 지원 · 원본 이름 찾기 · 최근 찾은 말 저장. 새 계약 없음 — `GET /api/experiences`(experience-api) · `POST /api/ask`(entrance-api)를 그대로 쓴다

#### F-11 다른 AI 에서 내 경험 꺼내 쓰기(MCP)

- 우선순위: `P0` (2026-11-04 PM — ETC#24 를 `P1` 에서 올림)
- 레포: BE · FE — 결정: [ADR-008](decisions/ADR-008-mcp-tools-in-be.md) · 쓰기는 [ADR-010](decisions/ADR-010-external-ai-write.md) · [ADR-011](decisions/ADR-011-external-ai-features.md)
- `S-32` 사용자가 연결 주소(또는 토큰)를 Claude 같은 MCP 클라이언트에 넣으면, 그 AI 에서 내 경험을 검색해 **근거(원본 이름 · 발췌) · 출처 상태 · 보완과 함께** 받는다 — 완료 조건(데모 7): 웹에서 쌓고 보완한 경험이 그대로 나온다. 기본은 읽기만 한다(쓰기는 사용자가 켠 연결에서만 — S-52 ~ S-56). 다른 사용자의 데이터는 보이지 않는다. 사용자가 연결을 끊을 수 있다. 연결을 만들 때 「연결하면 경험 · 근거가 그 AI 서비스(Claude 등)로 전송된다」를 알린다(기획 6.4)
- `S-52` 사용자가 연결 화면에서 **쓰기를 켜면** Claude 같은 외부 AI 가 대화 중 나온 글을 자료로 넣는다 — 우선순위 `P2`(ETC#27 · 2026-11-05) — 완료 조건: 쓰기는 기본으로 꺼져 있고, 연결 주소를 다시 만들면 다시 꺼진다. 꺼진 연결에는 쓰기 도구가 보이지도 불리지도 않는다. 켜는 자리에서 「외부 AI 가 자료를 넣고 경험 본문을 고칠 수 있다」를 알린다. 넣은 글은 사용자 확인 없이 바로 웹의 자료 넣기와 같은 분석(F-02)을 탄다 — 같은 하루 분석 한도 · 같은 글자 수 한도다. 그 경험의 근거에는 보낸 AI 이름(「Claude 에서 보냄」)이 보여 사용자가 직접 넣은 자료와 구분된다. 외부 AI 가 글을 요약했는지는 서버가 알 수 없으므로 「원문에서 확인」은 **보낸 글 안에서 확인했다**는 뜻이다. 분석이 실패하면 변경 기록에 실패 · 다시 시도가 보인다. 결정: [ADR-010](decisions/ADR-010-external-ai-write.md). 계약: [`contracts/mcp-api.md`](contracts/mcp-api.md) 「외부 쓰기 도구」
- `S-53` 쓰기를 켠 연결에서 외부 AI 가 경험의 **본문**을 고친다 — 우선순위 `P2`(ETC#27 · 2026-11-05) — 완료 조건: 사용자 확인 없이 바로 반영되고 그 경험은 「확인 필요」가 된다 — 「내가 입력」이 되지 않으므로 사용자가 확인하기 전엔 초안 · 근거 점검의 근거가 되지 않는다(S-27 · S-45). 화면에 「Claude 가 고침」 · 전 · 후 본문 · 고친 이유가 보이고, 사용자가 「맞아요」를 누르면 「내가 입력」이 된다. 근거 · 보완 · 역량 · 수행 주체는 바뀌지 않는다. 수행 주체 · 역량 고치기 · 경험 지우기는 웹에서만 한다 — 팀이 한 일을 내가 한 일로 바꾸는 사고를 막기 위해서다. 외부 AI 가 읽은 뒤 본문이 바뀌었으면 거절한다. 고친 이유는 필수다. 외부 AI 쓰기에는 하루 상한이 있다
- `S-54` 외부 AI 가 바꾼 것을 **변경 기록**에서 보고 건별로 되돌린다 — 우선순위 `P2`(ETC#27 · 2026-11-05) — 완료 조건: 최근 변경이 언제 · 어느 AI · 무엇을 · 왜와 함께 보인다. 경험 고치기를 되돌리면 이전 본문 · 출처 상태로 돌아간다. 자료 넣기를 되돌리면 그 분석이 만든 경험을 지우고, 사용자가 손댄 경험은 남기며 남긴 개수를 알린다. 원본은 남는다. 그 뒤 본문이 또 바뀌었거나, 분석 중이거나, 이미 정한 변경은 되돌릴 수 없고 이유가 보인다. 「맞아요」를 누른 변경은 웹에서 고친다(S-10). 이 변경 기록의 되돌리기는 외부 AI 변경에만 있다 — 웹 고치기까지 합친 항목별 이력은 S-80 이다. 외부 AI 가 만든 지원 · 전한 답도 같은 변경 기록에 있다(S-55 · S-56)
- `S-55` 쓰기를 켠 연결에서 외부 AI 가 사용자가 준 문항으로 **지원을 만들고 추천 결과를 읽는다** — 우선순위 `P2`(ETC#88 · 2026-11-05) — 완료 조건: 웹의 지원 넣기와 같은 규칙(문항 1 ~ 10개 · 글자 수 한도 · 문항마다 분석 1회)이고 사용자 확인 없이 바로 돈다. 만든 지원은 웹에 그대로 보인다. 외부 AI 는 요구사항 · 추천 · 되묻기를 읽는다 — 분석 중이면 분석 중으로, 실패하면 실패로 말한다. 초안 · 근거 점검은 열지 않는다. 저장 없이 결과만 돌려주는 매칭은 만들지 않는다. 변경 기록에서 되돌리면 그 지원이 지워진다. 분석 중이거나 사용자가 손댄 지원(되묻기 답 · 초안 · 근거 점검 · 확정 답 · 지원 상태 · 문항 더하기)은 되돌릴 수 없고 이유가 보인다. 되돌려도 쓴 분석 횟수는 돌아오지 않는다. 결정: [ADR-011](decisions/ADR-011-external-ai-features.md). 계약: [`contracts/mcp-api.md`](contracts/mcp-api.md) 「외부 쓰기 도구」
- `S-56` 쓰기를 켠 연결에서 외부 AI 가 사용자의 **되묻기 답**을 전한다 — 우선순위 `P2`(ETC#88 · 2026-11-05) — 완료 조건: 그 경험의 보완으로 저장돼 보이되 「Claude 를 거친 답」으로 구분된다. 사용자가 웹에서 「맞아요」를 누르기 전엔 「내가 입력」이 아니고 추천 · 초안 · 근거 점검의 근거가 되지 않는다(S-25 · S-27 · S-45). 경험 본문 · 근거 · 출처 상태는 바뀌지 않는다. 변경 기록에서 되돌리면 보완이 지워지고 그 되묻기에 다시 답할 수 있다. 사용자가 웹에서 답을 고치면 사용자 말이 된다(S-24). 확인 전 답은 근거에서 빠지므로 같은 사실을 다시 물을 수 있다. Markdown 내보내기(S-33)에는 확인 전 답을 싣지 않는다

#### F-15 공개 프로필 링크 — `P2`

- 우선순위: `P2` (ETC#35 · 2026-11-06 PM 기본값 — 기획 1.1 · 2.2 · 5-G · 7.2 「가벼운 공개 프로필 · 비공개 기록과 공개 경험은 기본적으로 분리」)
- 레포: FE · BE — AI 를 부르지 않는다
- `S-65` 사용자가 **고른 경험만** 실린 공개 프로필 링크 하나를 만든다 — 완료 조건: 기본은 아무것도 공개되지 않는다. 경험마다 「프로필에 넣기」를 사용자가 고르고, 고른 것이 0개면 링크를 만들 수 없다. 「확인 필요」 경험은 고를 수 없다 — 먼저 확인(「맞아요」 · 고치기)하라고 안내한다. 링크는 **추측할 수 없는 주소 하나**이고 로그인 없이 **읽기만** 한다. 링크를 만들 때 「링크를 아는 누구나 볼 수 있어요」를 알린다. 실리는 것: 프로필 제목 한 줄(선택 · 사용자가 씀), 활동 이름 · 기간 · 분류, 고른 경험의 본문 · 출처 상태(글자로) · 근거 원본 **이름**, 역량은 「AI 해석」 표시와 함께. 싣지 않는 것: 근거 **발췌문** · 원본 글 · 보완 원문 · 계기 한 줄(S-34) · 지원 · 다른 경험 — 비공개 원문이 새지 않게. 공개 페이지는 검색 엔진에 올리지 않는다(`noindex`). 경험을 고치면 공개 페이지에 바로 반영되고(그때의 사본을 따로 두지 않는다), 지운 경험은 빠진다
- `S-66` 사용자가 공개 링크를 **끄거나 새로 만들면** 옛 주소는 바로 막힌다 — 완료 조건: 막힌 주소 · 없는 주소는 같은 「없는 페이지예요」로 보인다(있었는지 알리지 않는다). 다시 켜면 새 주소다. 고른 경험 목록은 끄더라도 남는다. 공개 페이지에 다른 사람의 접근 기록 · 조회 수를 두지 않는다. 계약: [`contracts/share-api.md`](contracts/share-api.md)
- 범위 제외: SNS 피드 · 팔로우 · 댓글 · 검색으로 남의 프로필 찾기, 링크 여러 개(목적별 프로필), 비밀번호 · 기간 제한 링크, 공개 범위를 활동 단위로 한 번에 고르기, PDF · DOCX 내보내기(ETC#31)

#### F-16 시간 · 비용 돌아보기 — `P2`
