## 0. 개요

> 심사 「문제 정의 20 · 차별성 15」가 여기서 나온다([`hackathon.md`](hackathon.md)). 킥오프 틀: 누가 어떤 상황에서 어려운지 → AI 가 맡을 일 → 사람이 내릴 판단.

- 한 줄: 우리 팀은 활동 · 프로젝트를 여럿 해 봤지만 지원할 때마다 그 경험을 다시 찾아 정리하는 학생 · 초기 경력자의 반복 부담을 해결하려고, AI 가 흩어진 자료에서 경험을 근거와 함께 찾아 쌓아 두고 지원할 때 맞는 경험을 꺼내 부족한 사실만 묻는 서비스를 만든다
- AI 전후 한 줄: 원래 지원서 앞에서 노션 · README · 회고를 다시 뒤져 경험을 고르고 정리하던 걸, AI 가 자료를 근거 달린 경험으로 쌓아 두고 문항마다 맞는 경험을 꺼내 부족한 것만 묻는 것으로
- 대상 · 상황: 대학 시절 여러 프로젝트 · 활동을 해 본 학생과 초기 경력자. 동아리 · 부트캠프 · 대외활동 · 인턴 · 채용 지원 문항을 만났을 때
- 문제와 근거: 같은 경험을 지원할 때마다 다시 떠올리고 다시 쓴다. 학교 비교과 「경험MAP」은 학기별 경험 회상 → 직무 역량 연결 → STAR 재구성을 엑셀로 매번 손으로 채우게 한다. PM 이 옵시디언에 경험을 직접 관리하며 겪은 시행착오(팀이 한 일이 내 일로 기록됨 등). 설문 · 인터뷰는 보강 예정
- AI 가 맡는 일: 비정형 자료에서 활동과 경험을 뽑고 원문 근거를 단다 · 지원 문항의 의도를 읽고 맞는 경험을 찾는다 · 문항에 필요한데 자료에 없는 사실을 찾아 묻는다
- 사람이 판단하는 곳: 경험이 사실인지 · 내가 한 일인지 확인하고 고친다 · 어느 경험을 강조할지 고른다 · 최종 제출 문장
- 이미 있는 것과 다른 점: TIO(경험 관리 · 자소서) — 자료가 활동 목록에서 끝나지 않고 원문 근거가 달린 경험으로 쌓이고, 한 번 보완한 사실이 다음 지원에 다시 쓰인다

### 데모 흐름 (본선 시연 순서)

1. 팀 프로젝트 README · 회고를 넣는다 — 스프린트 1
2. AI 가 활동과 여러 관점의 경험을 뽑고 원문 근거를 단다 — 스프린트 1
3. 「기술 문제를 해결한 경험」 같은 지원 문항을 넣으면 맞는 경험을 추천한다 — 이후 스프린트
4. 직접 고친 부분 · 확인 방법처럼 부족한 사실을 묻는다(없는 수치를 지어내지 않는다) — 이후 스프린트
5. 짧게 답하면 경험에 쌓인다 — 이후 스프린트
6. 다른 문항에서 같은 활동의 다른 관점과 방금 보완한 사실이 다시 쓰인다 — 이후 스프린트
7. 외부 AI(Claude 등)에서 MCP 로 같은 경험을 검색한다 — 이후 스프린트

### 범위 제외

> 만들지 않기로 한 것만 둔다. 나중에 할 수 있는 건 여기 말고 `P2` 이슈(Backlog)로.

- 기업 분석 리포트 생성 · 합격 확률이나 점수 예측
- 채팅창이 메인인 AI · 모의 면접

## 1. 요구사항

### R-01 경험 관리 — 스프린트 1

> 목표 흐름: 자료 하나를 넣으면 → 활동과 근거 달린 경험이 카드로 나오고 → 고쳐서 저장하면 남는다.

용어 — 계약 · 코드에서 같은 뜻으로 쓴다. 화면 문구는 따로 정해도 된다.

| 용어 | 뜻 |
| --- | --- |
| 원본(Source) | 사용자가 넣은 자료 하나 — 붙여넣은 텍스트 또는 파일 |
| 활동(Activity) | 프로젝트 · 동아리 · 수업 · 대회 같은 한 덩어리. 이름 · 기간 |
| 경험(Experience) | 활동 안에서 실제로 한 일 하나 — 행동 · 결정 · 결과 · 배운 점. 활동 하나에 여럿 |
| 근거(Citation) | 경험을 뒷받침하는 원본의 발췌문 |
| 출처 상태 | 원문에서 확인 / 내가 입력 / 확인 필요 |
| 수행 주체 | 나 / 팀 / 알 수 없음 |

#### F-01 자료 넣기

- 우선순위: `P0`
- 레포: FE · BE
- `S-01` 텍스트를 붙여넣거나 `.md` · `.txt` 파일 하나를 올리면 분석이 시작된다 — 완료 조건: 원본 텍스트가 저장되고, 분석 작업의 상태를 조회할 수 있다
- `S-02` 분석 상태가 보인다: 분석 중 → 완료 / 실패 — 완료 조건: 실패하면 실패했다는 것과 「다시 시도」가 보인다(정해진 결과로 대신 채우지 않는다). 분석 중에 새로고침해도 상태가 이어진다

#### F-02 AI 경험 추출

- 우선순위: `P0`
- 레포: AI · BE
- `S-03` 원본 하나에서 활동 1개 이상과, 활동마다 경험 여러 개를 뽑는다. 경험마다 관점(예: 기술 구현 · 문제 해결 · 협업)이 붙는다 — 완료 조건: 활동이 여럿 섞인 자료(목록형 노트 등)에서도 활동별로 나뉜다
- `S-04` 경험마다 근거가 1개 이상 붙는다. 근거가 원본에 실제로 있는지 **코드로** 확인한다 — 완료 조건: 원본에 없는 근거를 단 경험은 「확인 필요」가 된다
- `S-05` 자료에 없는 수치 · 역할 · 결과를 만들지 않는다 — 완료 조건: 원본에 수치가 없으면 경험에도 수치가 없다
- `S-06` 수행 주체를 구분한다 — 완료 조건: 원본이 「팀이 했다」면 「나」로 바꾸지 않는다. 판단할 수 없으면 「알 수 없음」

#### F-03 경험 보기

- 우선순위: `P0`
- 레포: FE · BE
- `S-07` 활동을 연도별 타임라인과 목록으로 본다(둘 사이 전환) — 완료 조건: 분석으로 생긴 활동이 바로 나타난다
- `S-08` 활동을 열면 경험 카드가 보인다. 처음엔 몇 개만 보이고 나머지는 펼쳐 본다 — 완료 조건: 카드마다 관점 · 수행 주체 · 출처 상태가 보이고, 출처 상태는 색만이 아니라 글자로도 구분된다
- `S-09` 경험 카드에서 근거를 열면 화면을 떠나지 않고 원본 이름과 발췌문이 보인다

#### F-04 고치기

- 우선순위: `P0`
- 레포: FE · BE
- `S-10` 활동(이름 · 기간)과 경험(내용 · 관점 · 수행 주체)을 고쳐 저장하면 새로고침해도 남는다 — 완료 조건: 사용자가 고친 경험의 출처 상태는 「내가 입력」이 되고, 원래 근거(발췌문)는 그대로 남는다
- `S-11` 경험을 직접 추가하거나 지운다 — 우선순위 `P1`
