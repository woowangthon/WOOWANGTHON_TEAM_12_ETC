## 2. AI 기능

심사가 묻는 것: AI 가 **무엇을** 하고, **얼마나 믿을 만**하고, **사람은 어디서** 판단하나.

**왜 AI 인가** — 심사는 「문제에 AI 가 맞나 · 주요 기능에 실제로 얼마나 기여했나 · 오류와 한계를 검증했나」를 본다. 모델 이름이나 직접 학습 여부로는 점수가 오르지 않는다([`hackathon.md`](hackathon.md) 「심사」).

- **맞는 이유**: 자료가 회고 · README · 회의록 · 메모 · 자소서처럼 제각각이고, 같은 줄에 내 일과 남의 일이 섞인다. 활동을 나누고, 누가 했는지 읽고, 문항이 묻는 능력과 경험 본문을 맞추는 일은 형식 규칙 · 키워드 · 태그 일치로는 못 한다(매칭을 태그가 아니라 본문으로 판정하는 이유 — SPEC F-06).
- **AI 에 맡기지 않는 것**: LLM 이 약한 곳 — 근거를 지어내거나, 수치를 붙이거나, 남의 일을 내 일로 쓰는 것 — 은 코드와 사람이 막는다. 근거가 원본에 있는지는 코드가 대조하고(S-04), 출력이 계약 규칙을 어기면 다시 부르거나 오류로 돌려준다. 사실 여부 · 내 몫은 사용자가 고친다(F-04).
- **우리가 더한 몫**: 같은 모델에 「이 자료에서 내 경험을 정리해 줘」만 준 범용 프롬프트와 나란히 채점한다(아래 「추출 채점」). 매칭 · 되묻기도 같은 식으로 잰다(아래 「매칭 채점」 · 「되묻기 채점」).

## 5. 알려진 한계

발표 「오류와 한계」에 그대로 쓴다. 감추면 질의응답에서 잃는다.

- 근거 대조(S-04)는 발췌문 **글**이 원본에 있는지만 본다. 한 줄을 통째로 발췌하면(「서버는 한결, 앱 화면은 서윤, 나는 기관 담당자 연락…」) 남의 일이 섞인 줄로도 「원문에서 확인」이 된다 — 해석이 맞는지는 사람이 본다(F-04).
- `gpt-6.1-terra` 는 짧은 메모에서 활동을 통째로 빠뜨렸다 — 「토익 스터디 들어감. 3번 나가고 안 나감..」 2회 중 2회, 이력서의 「구청 행정 인턴」 2회 중 1회. 그래서 첫 모델을 `gpt-6-luna` 로 바꿨다. 빠진 활동은 사용자가 직접 더한다(S-11).
- `gpt-6-luna` 는 이웃한 문장을 한 경험으로 합치는 편이다 — 회의록의 「한결: QR 체크인 제안 · 서윤: … 의견 · 결정: …」을 경험 하나로, 「로그인과 알림 서버를 맡았다. FCM 으로 …」를 하나로. 내용은 남지만 경험 개수가 적다.
- `gpt-5.4-mini` 는 이력서의 「동아리 공동구매 사이트 개발」처럼 주어 없는 항목을 `TEAM` 으로 단 적이 있다(내 일을 덜 주장하는 쪽).
- 범용 프롬프트(`gpt-5.4-mini`)는 「지난 회의록 노션 정리」를 「회의 기록을 체계화했다」로 쓰는 등 원문에 없는 평가를 붙였다 — 우리 프롬프트 규칙 3이 막는 것. 수치 지어내기는 이번 자료에선 어느 쪽도 0건이었다.
- 수행 주체는 LLM 이 문장을 읽고 판단한다. 주어가 없는 팀 프로젝트 문장은 `UNKNOWN` 으로 두게 했지만 틀릴 수 있다 — 사람이 고친다(F-04).
- 폴백으로 모델이 바뀌면 결과 품질이 다를 수 있다. `gemini-3.5-flash-lite` 는 README 의 기능 목록까지 경험으로 뽑았다(1건 관찰). `gpt-6.1-terra` · `gpt-5.4-mini` 는 한 문장을 여러 경험으로 잘게 나누는 편이다(`gpt-6-luna` 는 덜함).
- MOC(활동 이력이 `[[링크]]` 목록인 노트)에서 링크만 있는 활동이 통째로 빠졌다 — 프롬프트 규칙 「경험이 없는 활동은 넣지 않는다」 때문(AI#18 에서 고침, 위 §2 표). 고치기 전 실제 노트(약 280줄, 로컬 1건, 2026-11-03)에서 `gpt-6-luna` 활동 5 · `gpt-6.1-terra` 9 · `gpt-5.4-mini` 17(링크 제목을 그대로 경험으로 만들고 한 활동을 둘로 나눔). 같은 노트를 TIO 에 넣으면 활동 목록만 뜨고 세부는 비었다(PM 경험). 노트 여러 개 · 폴더째 넣기는 ETC#29.
- 긴 입력은 느리다 — 위 280줄 노트에서 `gpt-6-luna` 40초(모델 한 번 제한 45초에 걸려 terra 로 넘어간 적 있음, 넘어간 시간 포함 81초) · `gpt-5.4-mini` 14초. 짧은 시험 자료 기준으로 고른 첫 모델 순서는 긴 실제 노트를 더 모으며 다시 본다.
- 한 번에 50000자까지 받는다(ai-api `TEXT_TOO_LONG`).
- 차곡이 `message` 의 사실 검사는 숫자 · 「」 이름이 도구 결과나 부탁에 있는지만 본다 — 팀 일을 내 일로 말하는 것은 프롬프트와 채점으로만 막는다. 문항 검사는 글자가 부탁에 있는지만 봐서, 부탁 말 자체(「OO 인턴 지원 만들어 줘」)를 문항으로 넣어도 통과한다(`mini` 1회 — 기본 모델에선 안 나옴). 사용자가 확인 카드에서 본다.
- 차곡이 채점의 시간은 가짜 MCP 라 네트워크 · DB 시간이 빠져 있다. `organizationType` · `jobRole` 값 목록은 BE 도구 스키마에 없어 AI 프롬프트에도 적었다 — 값이 늘면 두 곳을 고친다.
- 매칭은 사용자의 경험 **전부**를 한 번에 LLM 에 넘긴다(ADR-003). 경험 20개에 문항당 8 ~ 25초 — 경험이 수백 개가 되면 느려지고 글자 수 합 100000자를 넘으면 `TEXT_TOO_LONG` 이다. 그때 후보 줄이기(임베딩)를 붙인다.
- 답변 초안에서 `UNKNOWN` 경험은 누가 했는지 쓰지 않아 「코드가 수정됐습니다」처럼 문장이 덜 매끄럽다 — 사용자가 고친다. 이 표현은 코드로 막지 않고 프롬프트 · 채점으로만 본다.
- 초안의 숫자 대조는 문장에 붙인 글 · 활동 이름 · 기간에 **같은 숫자가 있는지만** 본다. 기간 `2025-03` 의 3 이 「3초」를 받치는 것처럼 뜻이 달라도 통과하고, 한글 수사(「세 번」)는 못 잡는다.
- 매칭의 이유 · 강조점이 맞는 말인지(인용한 근거와 뜻이 맞나)는 코드로 다 못 본다. 코드는 ID 가 요청에 있는지 · 같은 경험의 것인지 · 개수만 확인하고, 수치 · 「내 일로 말함」은 채점으로 잰다. 매칭 시험 자료는 지어낸 사용자 한 명이라 쉽다 — 실제 노트에서 뽑은 경험으로 더 본다.
- 되묻기의 「이미 있는 사실 다시 물음」 · 「수치 유도」 · 「막연한 질문」은 코드로 막지 않는다 — 손으로 적은 사실 12개 · 정규식으로 후보를 거르고 사람이 읽어 잰다. 정규식이 놓친 것(「어떻게 수정하셨나요?」)도 있어 질문 전부를 읽었다. 시험 자료가 지어낸 한 사람이고, 지금 프롬프트는 1회만 돌렸다.
- 되묻기는 추천한 경험에만 붙는다(계약) — 「맞는 경험이 없음」(추천 0개) 문항에선 아무것도 묻지 않는다. 자료에 없는 새 경험을 묻는 질문(「이런 경험이 있다면」)은 하지 않는다.
- 매칭에서 「확인 필요」 경험(근거가 원본에서 안 찾아짐)을 고를 수 있다 — 그때 부족한 점에 「근거가 원본에서 확인되지 않았습니다」를 단다(계약). 고르지 말아야 할지는 정하지 않았다.
- 홈 입력 가르기는 앞 4000자만 본다(BE 가 자른다) — 공고 앞부분이 회사 소개뿐이어도 제목 · 모집 단서가 보이면 지원으로 보게 했지만, 앞 4000자에 모집 단서가 하나도 없는 공고는 자료로 갈 수 있다. 다 쓴 자소서(문항 제목 + 답)는 자료로, 답 칸이 빈 문항은 지원으로 보게 했다 — 시험 입력이 지어낸 것이고 프롬프트를 쓴 에이전트가 같이 썼다. 이유(`reason`)는 AI 해석이다. 틀리게 갈리면 사용자가 모드 · 「다른 쪽으로 보내기」로 고친다(ADR-007).
- 지원 나누기는 지어낸 글로만 쟀다 — 실제 공고 · 링크(S-46) 숫자는 AI#39. 「글에 적혀 있나」는 글자가 있는지만 본다: 글에 적힌 문장이면 문항이 아니어도 통과하고, 그건 프롬프트 · 사용자 확인이 맡는다. 문항이 지원 양식(구글폼) 안에 있으면 찾지 못한다(`[]`). 글자가 조금만 달라도(마크다운 강조를 빼고 옮김 등) 규칙 위반이라 다시 부르고, 그래도 다르면 오류다. 문항이 10개를 넘으면 앞 10개만 나온다 — 사용자가 더 넣는다.
- 이어짐 제안은 지어낸 활동으로만 쟀다. 이유의 단정 · 지어낸 사연은 코드가 거르지 않아 프롬프트와 채점에 기댄다 — 「맞아요」를 누른 뒤에도 이유는 AI 해석으로 보인다. 경험이 많은 활동 20개를 실제로 넣은 시간은 재지 않았다(시험 자료의 후보 20개는 활동마다 경험 1 ~ 2개로 4초 안).
- 같은 활동 제안은 기존 활동의 이름 · 기간만 본다 — 이름이 전혀 다르고 고유한 이름도 없으면(「팀 프로젝트」 / 「캡스톤」) 놓친다. 같은 대회의 다른 회차처럼 이름이 같은 다른 활동은 붙이자고 할 수 있다(채점에서 2회 중 2회) — 자동으로 합치지 않으니 사용자가 「따로 두기」를 누른다. 기존 활동 100개를 실으면 추출이 조금 느려졌다(시험 자료 10건 합 158초 → 184초, 1회씩). 300개(BE 상한)는 재지 않았다.
- 기본은 OpenAI 유료 API(팀 크레딧 약 $100, 2026-12-01 만료). 크레딧이 떨어지면 429 → Gemini 키가 있으면 넘어간다.
- Gemini 는 무료 등급이라 입력이 Google 제품 개선에 쓰일 수 있고 Flash 모델마다 하루 20회 한도다 — 선택 폴백으로만 둔다. 배포에서 빼려면 `GEMINI_API_KEY` 를 비운다.
- 공고 링크(S-46)는 HTML 에 글이 있는 페이지만 읽는다 — 화면을 스크립트로만 그리는 페이지 · 포스터 이미지 공고 · 로그인 뒤 · 구글폼 안 문항은 못 읽고 「본문을 붙여 넣어 주세요」로 돌아간다. 게시판 머리글만 200자를 넘는 이미지 공고는 「읽힘」이 되고 문항 0개로 보인다. 실제 채용 공고엔 문항이 거의 없어(시험 1 / 16) 링크는 지원처 · 종류 · 직무 · 원문 링크를 채우는 데 주로 쓰인다.
- 공고 링크의 내부 주소 막기는 받기 직전 DNS 로 푼 IP 를 본다 — 확인과 연결 사이에 IP 가 바뀌는 DNS 재바인딩은 막지 못한다(연결 IP 고정은 안 함).
