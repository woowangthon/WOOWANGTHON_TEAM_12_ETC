# ADR-001: 레포 넷 · 명세는 ETC 문서 · 할 일은 GitHub Issue

- 상태: 채택
- 날짜: 2026-10-31

## 배경

- 운영진이 레포를 `WOOWANGTHON_TEAM_12_{FE/BE/AI/ETC}` 로 쪼개길 권했다(제출 양식도 이 이름). 제출은 레포마다 마감 시점 main 커밋 해시.
- 팀장이 지난 팀 프로젝트(이어봄)에서 쓴 흐름은 「Notion = 논의 · Manyfast = 명세 · GitHub = 구현」이었다. 이번엔 Manyfast 를 쓰지 않는다.
- 이어봄은 명세 반영 · 버전 저장 · 계획 승인 왕복이 무거웠고, 요구사항 맞추기에 시간을 쓰다 AI 쪽이 줄었다.

## 결정

| 무엇 | 자리 |
| --- | --- |
| 개발 명세 | ETC `docs/SPEC.md` (Manyfast 대신) — 이력은 git, 따로 버전 저장 안 함 |
| 레포 사이 계약 | ETC `docs/contracts/` |
| 결정 이유 | ETC `docs/decisions/` |
| 할 일 | GitHub Issue — 코드가 바뀌는 레포에. 걸치는 기능은 ETC 부모 이슈 + 레포별 하위 이슈 |
| 회의 · 일정 · 결정 배경 | Notion — 개발 요구사항으로 직접 쓰지 않음 |
| 공통 규칙 · 스킬 · 템플릿 | ETC 가 원본, `scripts/sync-shared.sh` 로 FE · BE · AI 에 복사 |

승인은 「되돌릴 수 있나」로 가른다. 되돌릴 수 있는 건 하고 나서 알리고, 정보가 없으면 묻고, 못 되돌리는 건 사람만.
main 은 PR 로만, 자기 영역 PR 은 본인 머지, SPEC · 계약을 바꾸는 PR 만 반대편 담당 승인, 11-15 17:00 부터 동결.

## 버린 안

- **모노레포 하나** — 계약 · 명세가 한 곳에 있어 가장 가볍다. 운영진 권장 · 제출 양식과 어긋나 버렸다.
- **명세를 FE · BE · AI 중 한 레포에** — 레포를 하나 덜 만든다. 나머지 둘이 남의 코드 레포에서 명세를 찾아야 하고, 계약의 주인이 한쪽으로 기운다.
- **명세를 Notion 에** — 팀원이 읽기 쉽다. 코드와 같은 이력에 묶이지 않고, 에이전트가 매번 커넥터로 읽어야 한다.
- **모든 PR 리뷰 필수** — 안전하지만 해커톤 속도에서 리뷰 대기로 막힌다. 레포 사이를 깨는 변경(계약 · SPEC)만 승인으로 남겼다.
- **세션 메모 파일(`.agent/current-task.md`)** — 이어봄 · 지난 프로젝트에서 썼다. 개인 PC 에만 있어 팀원이 못 본다. 인계는 이슈 댓글로.

## 결과

- 심사가 보는 README · ADR · 아키텍처가 ETC 한 곳에 모인다.
- 공통 블록을 고치면 sync 스크립트를 돌려야 한다 — 잊으면 레포마다 규칙이 갈린다.
