# ADR-004: OCI 서버 하나에 Docker Compose + Cloudflare Tunnel — 공개 전엔 Cloudflare Access 로 팀만

- 상태: 채택
- 날짜: 2026-11-02

## 배경

- 제출물에 인터넷에서 열리는 배포 링크가 들어가고, 심사가 끝날 때까지 유지해야 한다. 테스트 계정도 필요하다([`hackathon.md`](../hackathon.md)).
- BE 담당이 완성 전에 일찍 배포를 준비하려고 한다. PM 이 화면을 빨리 봐야 해서(ADR-002) 일찍 배포하는 게 맞다.
- LLM 호출은 돈이 든다. 로그인 없이 공개하면 누구나 분석을 돌릴 수 있다.

## 결정

- **OCI 서버 하나에 Docker Compose** 로 BE · AI · DB(필요하면 FE)를 띄우고, **Cloudflare Tunnel** 로 내보낸다.
- **터널로는 FE · BE 만 내보낸다.** AI 서버와 DB 는 Compose 내부망에만 둔다([ADR-003](ADR-003-stack-and-ai-boundary.md)).
- **로그인이 붙기 전엔 Cloudflare Access 로 팀원 이메일만 들어오게 막는다.** 코드가 필요 없어서 BE 는 그동안 스프린트 1 흐름(BE#4 · BE#5)을 먼저 한다.
- **공개 전에 로그인과 사용 한도를 붙이고 Access 를 푼다**(SPEC R-02). 한도는 세 겹이다 — 사용자별 하루 분석 횟수(BE · DB 카운터), 입력 크기 상한, LLM 제공사 콘솔의 사용 한도.
- FE 와 BE 는 같은 상위 도메인 아래에 둔다(예: `app.` · `api.`). 로그인 쿠키 · CORS 를 단순하게 하려고. FE 를 어디서 띄울지(Compose · Cloudflare Pages 등)는 FE · BE 담당이 정한다.
- 서버 · 도메인 · 비밀값은 사람만 다룬다. 레포엔 `.env.example` 만.

## 버린 안

- **PaaS(Render · Railway 등)에 서비스별 배포** — 설정이 적다. 하지만 서비스가 셋(BE · AI · DB)이라 무료 한도 · 잠자기(cold start)에 걸리고, 심사 기간 내내 유지하기 불안하다.
- **로그인부터 만들고 배포** — 처음부터 공개 구조가 맞다. 하지만 스프린트 1 흐름이 로그인에 막혀 늦어진다. Access 로 막아 두면 같은 효과를 코드 없이 얻는다.
- **포트를 열어 직접 공개(Nginx + 인증서)** — 익숙하다. 하지만 서버 방화벽 · 인증서 관리가 늘고, 터널은 포트를 열지 않아도 된다.

## 결과

- 일찍부터 실제 주소에서 화면을 본다. AI 서버가 밖에 없어 LLM 키 · 비용이 새는 길이 BE 하나로 준다.
- 서버가 하나라 그 서버가 죽으면 다 멈춘다. 심사 기간엔 상태를 지켜봐야 한다.
- OCI 무료 서버(ARM)를 쓰면 이미지를 arm64 로 빌드해야 한다.
