# ADR-007: 입력 하나(차곡이) — P0 는 가르기, P1 은 우리 API 를 도구로 쓰는 호출 루프

- 상태: 채택
- 날짜: 2026-11-04

## 배경

- 디자인 시안 6(ETC#19 · ETC PR #73)에서 홈 입력칸 하나로 쌓기 · 꺼내기를 다 받기로 했다. 사용자는 한 줄 질문이든 지원 문항이든 자료든 그냥 붙여 넣고, AI 가 알아서 맞는 기능으로 이어 주기를 기대한다(PM, 2026-11-04 — 「Claude Code 처럼 끊김 없이」).
- [ADR-003](ADR-003-stack-and-ai-boundary.md) 은 「LangGraph 는 지금 쓰지 않는다 — AI 흐름은 함수 몇 개로 잇고, 분기 · 상태가 생기면 그때 검토」였다. 입력을 해석해 여러 기능을 고르는 건 그 분기다.
- 제출은 11-15. 스프린트 2(R-03)의 `P0` 가 아직 돌고 있다.
- SPEC 범위 제외에 「채팅창이 메인인 AI」가 있다.

## 결정

- **P0 — 가르기(S-28):** 홈 입력에 넣은 글을 AI 가 한 번 보고 **「자료(쌓기)」 / 「문항 · 공고(지원)」** 로 가른 뒤 이미 있는 흐름(S-01 자료 넣기 · S-18 지원 넣기)으로 넘긴다. 애매하면 사용자에게 묻는다. 입력칸 아래 모드(꺼내기 / 쌓기)로 사용자가 직접 정할 수도 있다. LLM 호출 한 번 + 분기 — 함수로 짠다(LangGraph 없음).
- **P1 — 도구 호출 루프(S-31):** 우리 BE API(경험 찾기 · 활동 보기 · 자료 넣기 · 지원 만들기 · 보완 저장 …)를 **도구로 쥐고**, 한 입력을 여러 단계로 처리한다. 단계마다 진행을 보이고, **저장 · 변경은 사용자 확인 뒤**에만 한다. 라이브러리(LangGraph · LLM 공급자의 함수 호출)는 시작할 때 고른다.
- **같은 도구를 밖에도 연다:** MCP(S-32, ETC#24)가 쓰는 도구와 차곡이의 도구를 같은 목록으로 둔다 — 안에서는 차곡이가, 밖에서는 Claude 같은 다른 AI 가 쓴다(기획 6.3 의 MCP 도구 예시가 그 목록의 시작).
- **차곡이는 자유 대화 상대가 아니다.** 우리 기능(쌓기 · 꺼내기 · 근거 찾기 · 되묻기)을 부르는 입구다. SPEC 범위 제외 문구를 이렇게 고친다.
- AI 서버가 DB 를 만지지 않는다는 ADR-003 경계는 그대로 — 도구는 BE API 를 부른다.

## 버린 안

- **처음부터 도구 호출 에이전트** — 가장 매끄럽다. 하지만 11-15 까지 R-03 P0 와 같이 만들기 어렵고, 루프가 틀리면 데모 흐름 전체가 흔들린다.
- **에이전트 안 함(화면마다 버튼만)** — 단순하다. 하지만 「한 입력으로 알아서」라는 시안의 핵심 장면이 빠지고, MCP 와 같은 도구 목록을 나눠 쓰는 그림도 없어진다.
- **채팅창을 화면 본체로** — 다른 AI 서비스와 같아지고, 「경험이 본체」 원칙(SPEC §0)과 부딪친다.

## 결과

- P0 는 기존 흐름에 입구 하나만 더한다 — 위험이 작다.
- P1 에서 도구 목록을 MCP 와 같이 쓰면 「같은 경험을 어디서든」이라는 차별점(Notion 「차별점 정리 v261104」)이 구조로 보인다.
- 남은 위험: 가르기가 틀리면 사용자가 한 번 더 고쳐야 한다 — 모드 토글과 「다른 쪽으로 보내기」를 늘 둔다.
