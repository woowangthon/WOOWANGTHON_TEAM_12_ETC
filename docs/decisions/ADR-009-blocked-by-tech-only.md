# ADR-009: 선행(blocked by)은 기술 의존에만 — 우선순위는 라벨이, 손이 비면 P1 도 한다

- 상태: 채택
- 날짜: 2026-11-05

## 배경

- 대회 규칙 4 「SPEC 의 `P0` 가 다 돌기 전엔 `P1` 을 시작하지 않는다」와 ADR-002 「다음 스프린트 기능을 미리 만들지 않는다」를 따르느라, ETC#25(PDF · PPTX, `P1`)의 하위 이슈를 `P0` epic(ETC#81)에 선행으로 걸었다. 그런데 두 쪽 코드는 서로 기다리지 않았다.
- 서버 담당이 하루 비어 `P0`(운영 설정 · S-28 의 BE 쪽)가 멈춘 동안, 손이 빈 사람도 `next-up` 에서 `P1` 을 「대기」로 보게 됐다. 사람이 이슈를 가져가는 방식(ADR-002)에서 순서 규칙이 일을 막으면, 마감 전 시간을 버린다.
- 순서를 보여 주는 도구는 이미 있다 — 라벨(`P0`/`P1`/`P2`) · Milestone · `next-up` 정렬.

## 결정

- **선행은 기술적으로 막힐 때만 건다** — 그 이슈가 끝나야 이 이슈를 시작하거나 끝낼 수 없을 때. 예: 계약 · API · 스키마 · 공용 코드 · 그 기능 위에 얹는 기능(MCP 서버 → MCP 쓰기 도구).
- **선행으로 걸지 않는 것** — 우선순위(`P0` 먼저) · 스프린트 순서 · 담당자 일정 · 「데모가 먼저」 같은 순서 판단. 이건 라벨 · Milestone 이 보여 주고 `next-up` 이 정렬한다.
- **대회 규칙 4** 를 「손이 비면 `P0` 부터 가져간다. `P0` 가 사람 · 외부 사정(담당 부재 · 운영 설정 대기 등)으로 멈춰 있으면 `P1` 을 해도 된다」로 바꾼다. 「데모에 없는 설정 · 추상화 · 확장 지점을 만들지 않는다」는 그대로.
- ADR-002 의 「다음 스프린트 기능을 미리 SPEC · 코드에 만들지 않는다」는 위 규칙 4 로 대체한다. 스프린트 · 화면을 보며 고치기 · 담당을 미리 정하지 않기는 ADR-002 그대로.
- 영향: ETC `AGENTS.md` 공통 블록 · `plan-feature` · `implement-issue` · 이슈 템플릿 → `sync-shared.sh` 로 FE · BE · AI. 우선순위만으로 걸었던 선행(ETC#25 · FE#79 · BE#48 ← ETC#81)을 푼다.

## 버린 안

- **우선순위도 선행으로 건다(지금까지)** — `next-up` 하나로 「무엇부터」가 강제된다. 하지만 사람이 비면 기술적으로 할 수 있는 일까지 막히고, 「대기」의 이유가 코드인지 일정인지 구분되지 않는다.
- **규칙 4 를 없앤다** — 가장 자유롭다. 하지만 마감이 가까워 데모 흐름이 덜 돈 채 `P1` 이 늘 수 있다. 「손이 비면 `P0` 부터」는 남긴다.

## 결과

- `next-up` 의 「대기」는 기술적으로 막힌 것만 남고, 손이 빈 사람은 `P1` 을 바로 가져간다.
- 「`P0` 가 멈췄나」는 가져가는 사람이 판단한다. `P0` 를 두고 `P1` 을 가져갈 땐 그 이슈에 이유 한 줄(「BE#44 운영 설정 대기 중」 등)을 남긴다.
- 위험: `P1` 이 `P0` 보다 앞서 쌓일 수 있다 — PM 이 `next-up` 으로 스프린트 진행을 보며 잡는다.
