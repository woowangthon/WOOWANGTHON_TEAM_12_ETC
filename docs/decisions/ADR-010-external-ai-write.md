# ADR-010: 외부 AI 쓰기는 바로 반영하고, 고친 글은 「확인 필요」로 낮추고, 웹에서 되돌린다

- 상태: 채택
- 날짜: 2026-11-05

## 배경

- ETC#27 — Claude 같은 외부 AI 대화 중 나온 기록을 우리 앱에 넣고 고치고 싶다. [ADR-008](ADR-008-mcp-tools-in-be.md) 은 「외부 AI 의 쓰기는 경험을 직접 고치지 않고 원본으로 들어온다」고 했고, SPEC S-32 · 이슈는 「사용자 확인 뒤」라고만 적어 두었다.
- 대화 중에 웹으로 가서 건마다 승인해야 한다면 MCP 로 쓰는 이유가 줄어든다. 하지만 차곡이의 확인 카드는 우리 화면 안에서만 뜨고, 외부 AI 의 프롬프트 · 승인 설정은 우리가 강제할 수 없다.
- 지금 `PATCH /api/experiences/{id}` 는 고치면 `USER_ENTERED`(내가 입력)가 되고, 초안 · 근거 점검은 그 본문을 사실 근거로 쓴다. 같은 길을 태우면 외부 AI 가 쓴 문장이 사용자 말이 된다(제품 원칙 「원문 · 사용자 말 · AI 해석을 구분한다」).

## 결정

- **쓰기는 연결마다 따로 켠다.** 기본은 꺼짐. 켜면 토큰 범위가 `READ` → `READ_WRITE`. 주소를 다시 만들면 다시 꺼진다.
- **쓰기는 사용자 확인 없이 바로 반영한다.** 확인은 앞에서 막는 대신 뒤에서 되돌리는 것으로 바꾼다. 차곡이(S-31)의 「확인 뒤 실행」은 그대로다 — 이 ADR 은 외부 AI 에만 적용한다.
- **외부 AI 가 고친 경험은 `NEEDS_REVIEW` 로 낮춘다.** 근거 · 보완 · 역량 · 수행 주체는 그대로 둔다. `NEEDS_REVIEW` 본문은 이미 근거로 쓰이지 않으므로 새 상태값 없이 초안 · 근거 점검에서 빠진다. 사용자가 웹에서 「맞아요」를 누르면 `USER_ENTERED` 가 된다.
- **도구는 둘만 연다.** `add_source`(기존 추출 · 근거 대조 · 분석 한도를 그대로 탄다) · `update_experience`(본문만). 지우기 · 수행 주체 · 역량 · 보완 저장은 열지 않는다 — 수행 주체는 「팀이 한 일」을 「내가 한 일」로 바꾸는 사고를 막으려고, 보완은 「내가 입력」이라 위 문제가 그대로 생겨서.
- **외부 AI 가 바꾼 것만 변경 기록에 남긴다**(전 · 후 값 · 보낸 AI · 이유). 웹에서 건별로 되돌린다.
- **강제는 BE 코드로 한다.** `instructions` · 도구 설명은 권고일 뿐이다. 토큰 주인의 경험만 · 읽은 본문과 다르면 거절 · 이유 필수 · 하루 상한 · 입력 크기는 코드가 막는다.

영향: SPEC `S-52` ~ `S-54` · `S-32` · 미결정 23, 계약 `mcp-api.md` · `experience-api.md` · `README.md`, BE · FE 하위 이슈(ETC#27). ADR-008 의 「외부 AI 의 쓰기는 경험을 직접 고치지 않고」 항목을 대체한다. 나머지는 유효하다.

## 버린 안

- **앱 안 확인 대기함** — 호출은 대기로만 저장하고 사용자가 웹에서 넣는다. 확인을 강제할 수 있고 세션 문제도 없다. 하지만 대화가 끊기고, 쌓이기만 하면 쓰이지 않는다.
- **외부 AI 의 도구 승인에만 맡김** — BE 만 고치면 된다. 하지만 사용자가 「항상 허용」을 켜면 확인이 사라지고, 되돌릴 길이 없다.
- **고친 글을 `USER_ENTERED` 로 저장** — 지금 코드 그대로다. 하지만 되돌리기 전에 만든 초안에는 이미 근거로 들어간다.
- **새 출처 상태값(`AI_EDITED` 등)** — 뜻이 가장 정확하다. 하지만 FE · BE · AI 가 값 세 개를 나눠 쓰는 곳을 모두 고쳐야 하고, 지금 `NEEDS_REVIEW` 가 하는 일과 같다.
- **경험 전체 버전 관리** — 웹 고치기까지 되돌릴 수 있다. 하지만 이 문제에 필요한 것보다 크다.

## 결과

- 대화를 끊지 않고 쌓는다. 잘못 들어와도 초안 근거로 번지지 않고, 사용자가 건별로 무른다.
- 포기한 것: 쓰기 전 확인. 외부 AI 가 요약한 글을 원문처럼 보내는 것은 서버가 막지 못한다 — `add_source` 의 「원문에서 확인」은 **보낸 글 안에서 확인했다**는 뜻이고, 근거에 보낸 AI 이름이 보인다.
- 남은 위험: 외부 AI 가 읽은 문서 속 지시로 쓰기를 부를 수 있다(프롬프트 인젝션) — 되돌리기와 하루 상한으로 줄일 뿐 막지는 못한다. 연결 주소가 새면 쓰기까지 열린다 — 기본 꺼짐으로 줄인다. MCP 호출에는 웹 세션이 없어 서비스 코드가 사용자 ID 를 받게 고쳐야 한다.
