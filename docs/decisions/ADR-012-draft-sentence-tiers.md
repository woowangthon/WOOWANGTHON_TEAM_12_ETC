# ADR-012: 초안은 근거 · AI 보탬 · 빈칸으로 구분해 쓴다

- 상태: 대체됨 → ADR-014
- 날짜: 2026-11-07

## 배경

- 스프린트 3 까지 만든 뒤 실제로 써 보니 초안이 「…관리됐습니다」처럼 경험을 한 줄씩 옮긴 글이 됐다. 받칠 근거가 없으면 쓰지 않는 규칙 때문에 빈칸을 사용자가 다 메워야 했고, 지원서 분량을 채울 수 없었다.
- 원인: 경험 31개 중 20개가 `UNKNOWN` 이라 주어를 쓰지 못했고, 고른 경험 1 ~ 3개만 AI 에 갔으며, 목표 분량이 없었다. 쌓인 경험은 사람이 말을 더해 쓸 색인에 가까운데 그대로 옮기고 있었다.

## 결정

- **문장을 세 등급으로 쓴다.** 근거(`FACT`) · AI 보탬(`ELABORATED`, 표시 필수) · 빈칸(`[결과]`, 사용자만 아는 값). 「안 쓴다」에서 「쓰되 구분해 보인다」로 옮긴다.
- **넘지 않는 선은 코드와 채점으로 지킨다.** 수치는 코드가 대조하고, 성과 · 직책 · 기술 이름 · 감정은 빈칸으로 둔다. `TEAM` 일은 내 일로 쓰지 않는다.
- **재료를 넓힌다.** 같은 활동의 나머지 경험을 싣고, 주체는 활동 단위로 한 번에 확인한다.
- **표시는 글 위에 둔다.** 문장마다 블록을 두지 않고 교정 화면처럼 표시를 눌러 확인한다.

영향: SPEC §0 · `S-15` · `S-27` · `S-73` ~ `S-79` · 미결정 28, 계약 README · `question-api.md` · `ai-api.md` · `experience-api.md` · `auth-api.md`.

## 버린 안

- **지금 규칙 유지** — 근거 없는 문장이 없어 안전하다. 하지만 분량을 못 채우고 사용자가 매번 답해야 해 쓰지 않게 된다.
- **표시 없이 자연스럽게 채우기** — 글은 가장 매끄럽다. 하지만 범용 LLM 과 같아지고 고정 사실처럼 보여 지원서에 지어낸 사실이 들어간다.
- **`OPINION` 을 넓히기** — 값을 안 늘려도 된다. 하지만 `OPINION` 은 근거 0개 · 앞으로의 말이라 지난 일을 풀어 쓴 문장과 뜻이 다르고, 뼈대 근거를 보일 수 없다.
