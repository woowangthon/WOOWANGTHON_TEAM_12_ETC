# ADR-019: 한 번 정리한 STAR 는 AI 로 다시 정리하지 않는다 — 비어 있는 것만 BE 가 알아서

- 상태: 채택
- 날짜: 2026-11-12

## 배경

- ADR-018 은 이미 쌓인 경험(`NONE`)과 함께, 정리한 뒤 근거 · 보완이 바뀐 경험(`STALE`)도 BE 가 알아서 다시 정리하기로 했다(BE#180 — 같은 활동은 마지막 변경 뒤 30초 모아 한 번).
- BE#180 을 시작하며 PM 과 다시 짚었다(2026-11-12). PM 이 거슬렸던 건 **활동 화면마다 떠 있던 「STAR 로 정리」 버튼**이었다. 그 원인은 STAR 기능 전에 만든 경험이 비어 있어서다. 「다시 정리」 자동은 그 불편과 상관없이 덧붙은 것이었다.
- 다시 정리는 보완을 고치거나 지울 때마다 유료 `/star` 호출을 하나씩 만들고, 다시 정리해도 사용자 답 칸을 지키는 병합 규칙이 따로 필요하다.

## 결정

- **비어 있는 STAR(`NONE`)만 BE 가 알아서 정리한다** — 배포 뒤 몰아서 + 이후 자료 분석 밖에서 생긴 경험도. 분석 횟수를 세지 않는다. 동시 호출은 2개까지.
- **한 번 정리한 경험은 근거 · 보완이 바뀌어도 AI 를 다시 부르지 않는다.** `STALE` 을 만들지 않고(값은 계약에 남김), 있던 `STALE` 은 `READY` 로 돌린다. 칸은 실제 글만 가리키게 코드가 맞춘다 — 가리키던 글이 사라진 칸은 빈칸, 수행 주체가 `ME` 에서 바뀌면 근거로 찬 T 칸은 빈칸. 나머지는 사용자가 칸을 그 자리에서 고친다(S-96).
- `FAILED` 의 「다시 시도」는 그대로(세지 않음).

영향: SPEC S-95 · S-96 · 미결정 31, 계약 `experience-api.md` 「STAR 칸」 · README `starStatus` · `ai-api.md` 「POST /star」 부르는 곳, `ai-scope.md` F-18 줄. 레포 BE(BE#180) · FE(FE#515 — `STALE` 이 오지 않는다).

## 버린 안

- **`STALE` 이 되면 30초 모아 BE 가 다시 정리(ADR-018)** — 바뀐 근거가 칸에 저절로 반영된다. 버린 이유: 원래 불편(버튼)과 상관없고, 수정마다 유료 호출이 늘며, 사용자 답 칸을 지키는 병합이 따로 필요하다.
- **`STALE` 은 표시만 하고 아무도 다시 정리하지 않기** — 코드 변경이 가장 적다. 버린 이유: 버튼을 없앤 뒤엔 사용자가 할 수 있는 게 없는 상태 표시라 화면만 헷갈린다.

## 결과

- 몰아 정리 한 번 뒤로는 `/star` 가 새 경험에만 불린다.
- 경험을 합치거나 보완을 늘려도 STAR 칸에 저절로 들어가지 않는다 — 사용자가 칸을 고쳐 넣는다.
- (2026-11-12 PM · BE#184) 칸 밖에 새 답이 쌓이면 사용자가 **경험 하나를 눌러** 다시 나눌 수 있다(`star.hasNew` 일 때만 버튼 · 세지 않음 · 사용자가 쓴 칸은 지킨다). 자동이 아니라 누르는 길을 더한 것이라 이 결정은 그대로다. 사용자 칸을 지키는 병합 규칙은 이때 생겼다.
