# 결정 기록 (ADR)

심사 「기술 설계 · 이해도」와 질의응답 「왜 이 기술을 썼나요?」의 답이 여기 있다. 발표 전에 한 번 훑는다.

## 무엇을 남기나

**되돌리기 비싼 결정만** — 스택, 저장소, AI 모델 · 외부 API, FE · BE · AI 경계, 배포처, 팀 워크플로.
라이브러리 하나 · 폴더 이름은 커밋 메시지로 충분하다.

## 규칙

- **정한 뒤에 쓴다.** 제안서가 아니라 기록이다. 아직 못 정했으면 `SPEC.md` 「미결정 질문」에 둔다.
- [`000-template.md`](000-template.md) 를 복사해 `ADR-NNN-<짧은-이름>.md`. 번호는 다음 숫자, 겹치면 나중에 머지하는 쪽이 바꾼다.
- **한 쪽 분량.** 버린 안을 하나 이상 적는다 — 버린 안이 없었다면 결정이 아니라 사실이다.
- 상태는 둘: `채택` · `대체됨 → ADR-NNN`.
- **결정이 바뀌면** 옛 ADR 을 고치지 않는다. 같은 PR 에서 새 ADR 을 쓰고(무엇이 왜 바뀌었나), 옛것은 상태 줄만 `대체됨 → ADR-NNN` 으로.
- `SPEC.md` · `architecture.md` · `ai-scope.md` 에 영향이 있으면 같은 PR 에서 고친다.
- 색인 표는 두지 않는다 — 이 폴더 목록이 색인이다.
